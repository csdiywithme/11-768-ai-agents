# B300 GEMM：指标下降后，候选为什么仍然变慢

## 输入与证据范围

研究对象是 NVIDIA B300 SXM6 AC 上预量化的 `4096×4096×4096` GEMM。FP8 与 NVFP4 分开分析。CUDA 13.1 镜像使用 NCU 2025.4.1.0。原生 NCU 采集在预热后做 40 次 replay，未锁频，不同报告可能来自不同 B300 分配。性能结论采用同次分配内的 GPU event 对拍。 [采集口径](/Users/simida/csdiy/wmhpc-training-camp-x-lcpu-ai-infra-seminars/assignment02/experiments/m4_lowprec_20261022/NCU_ANALYSIS.md:5)

## 瓶颈与待检验解释

- **已见的返工。** FP8 屏障、FP4 向量 load、FP4 scale/TMA 重叠各经过代码变体、正确性验证、同轮计时和诊断回查。记录能定位变体和决定。个人用时、人工改动次数和人机分工未知。
- **重复操作。** 每个变体都要匹配源文件和原始产物，核对精度、形状、grid、计时口径和 reference。日志字段及 SHA 可用程序检查。 [实验流水账](/Users/simida/csdiy/wmhpc-training-camp-x-lcpu-ai-infra-seminars/assignment02/experiments/m4_lowprec_20261022/NCU_ANALYSIS.md:68)
- **判断瓶颈。** scale 加载延迟、驻留受限与重复工作共同决定结果。提高 grid cap 的同 kernel 对照支持并发贡献。不同形状可能改变片上缓存命中率，导致重复流量或尾波抵消收益。可用相同 BN128 的 cap 对照，加不同形状和缓存条件，分别观测驻留、首次 miss、有效吞吐和正确性。 [新增流量和剩余瓶颈](/Users/simida/csdiy/wmhpc-training-camp-x-lcpu-ai-infra-seminars/assignment02/experiments/m4_lowprec_20261022/NCU_ANALYSIS.md:64)

## 可验证的产物

先比较原手工流程与可读取 stdout 和 NCU CSV 的证据整理工具。验收样本包含四种错误陈述：把 NCU replay 时间当作正式计时，把 grid cap 当作实测驻留，把少量计数下降当作加速，以及把 GEMM-only 吞吐写成端到端收益。脚本可检查数值和字段。结论的适用范围可交给同一份 rubric 检查。

如果相同资料和工具已充分提供，模型仍反复误读硬件条件，再试做人工核验的示范。按 kernel 家族和硬件代际留出评估案例，避免把同一轮不同变体拆到训练和评估两侧。
