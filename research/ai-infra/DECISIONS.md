# 证据复核的机会与对照设计

本页保存 2026-11-12 基于首批案例提出的证据复核设计。2026-11-13 已补选题、候选、执行和反馈调整的案例。当前的工作机会排序和首项验证见 [工作机会比较](OPPORTUNITIES.md)。

## 三个案例共同指向什么

| 案例 | 已观察到的工作 | 主要瓶颈 | 还缺的证据 |
|---|---|---|---|
| [B300 GEMM](cases/01-b300-gemm.md) | 同一个问题查源码、编译产物、正确性、GPU event 和 NCU 多种证据。部分计数改善后延迟反而上升 | 重复核对和解释指标。适用的硬件、shape 和 baseline 容易在转述中丢失 | 哪些字段可稳定自动提取，哪类结论最常需要人工纠正 |
| [vLLM 调度](cases/02-vllm-scheduler.md) | 逐轮对齐状态、剩余块和 token 配额。教学回放、上游报告和历史回归各有范围 | 定位状态分歧和辨别失败类型。运行记录不足会把导入错误误计为目标回归 | 本地历史上游测试与服务实测。相邻版本上的状态定位能否迁移 |
| [DeepInfer profiling](cases/03-deepinfer-profiling.md) | 分开计时与 trace，再逐步隔离传输失败。已有组件数据给出量级 | 多源证据对齐，缺关键路径和传输能力证明 | 同请求完整时间线、成功的目标传输、无 profiler 的端到端对照 |

本地资料证明有反复核对和解释的工作。三个案例都没有同任务的人工作时基线，也没有记录 Agent 在相同证据条件下的失败频率。首轮调研据此提出验证证据错误和人工返工。关于信息检索、工具和模型能力的相对贡献仍是待验证假设。

扩展复核使用 [MiniMax M3 MSA decode](cases/04-minimax-msa-pdl.md)。PDL 开启时总体仍加速，但四种形状在两个 seed 均退化。它加强了先检查适用条件与负向切片的理由。该案例已用于设计，后续需要另找独立留出样本。

## 交付形态比较

| 形态 | 优先改善的步骤 | 输入与验收 | 成本与维护 |
|---|---|---|---|
| 证据索引 | 找到同一次实验的配置、源码、计时、trace 和结论 | 从结论反查原始证据。抽查版本、硬件、范围和反例是否齐全 | 录入和链接更新。格式变化时仍可人工使用 |
| 小脚本或工具 | 核对 shape、commit、运行 ID、计时类型、断言和分母 | 已保存的 CSV、JSON、stdout 或源码。用可信错误样本检查能否报出具体不一致 | 每种格式需要解析器。源文件和计算逻辑可分别维护 |
| 固定工作流 | 让可预见的步骤先执行，例如预检、正确性、配对测量、报告 | 输入输出有稳定结构。验证中断恢复、失败分类和人审节点 | 要维护分支和状态。异常类型多时增加改动 |
| Agent 或 harness | 根据新证据选择下一个查证动作。保留多轮状态与权限 | 有稳定的只读工具、证据记录、停止条件和任务评估。比较自由探索是否发现固定流程漏掉的原因 | 运行与调试成本较高。需要处理调用失败、上下文和复核 |
| 评估集 | 识别什么回答真的改进决策 | 用历史案例和可信反例。把参考结论从输入隐藏。保留独立题族 | 需要人工评审和维护标签。可为其它路线共用 |
| 人工核验的示范 | 把难以写成硬规则的判断变成可审阅过程 | 短轨迹中保留证据、判断、未知和下一步。检验同一模型在有无示范时的差异 | 每条示范需要复核。资料变更可能使示范过时 |
| SFT 数据 | 改善在充分证据和工具下仍反复出错的目标行为 | 先验证标签一致性。记录版本、输入证据、目标输出和权限。以任务家族、PR 或版本分组留出。比较基础模型、工具或示范基线与训练模型 | 标注、去重、训练与长期回归成本。三个历史案例只能作为种子。样本数与效果目前无法估计 |
| 现有手工做法 | 给其它路线提供基线 | 使用相同材料、问题和判分口径，记录工作时间、人工修正和漏证据 | 当前成本待测。保持原有工具和资料可用 |

依据来自 [A2 的评估和失败反例](notes/evaluation-and-operations.md)、[课程编排与持久化](notes/evaluation-and-operations.md#l15--固定工作流与开放式调查)、[SFT 数据专题](notes/training-sft-data.md)、[检索与证据专题](notes/training-research-and-retrieval.md) 和 [一手资料扩展](sources/exploration.md)。

## SFT 的数据条件

当前可稳定复核的标签集中在版本、计时口径、正确性、引证位置和适用范围。关键路径归因及下一步诊断仍可能有多种合理答案。现有四个案例足以做种子和反例，不能据此估计训练收益或训练样本量。先在新案例上用两位评审独立标注，检查是否能稳定区分已证实、被反驳和证据不足。若仍有一致的判断错误，再保存带原始证据的示范。按 kernel 家族、PR 或系统运行批次分组留出，同一根因的变体放在同一侧。[SFT 证据与数据来源](notes/training-sft-data.md)

## 首轮提出的证据复核验证

做一份**离线证据复核评估**。输入用三个案例的现有产物。以现有人工流程为工作基线。另做同模型对照，固定任务、语料快照、工具与预算，先比较原检索方式和直接给出证据包。证据包只增加原始片段、位置与客观来源字段。专家推导和参考答案由评审方单独持有。若直给改善，增加只给文件与定位线索的条件，让模型自己读取。若证据已进入输入而仍有误判，再固定证据包，仅添加硬检查。这样可以分别定位查找、读取与核验的成本。现有材料可用于这项验证。

1. 每个案例准备一份成立的判断和一份容易漏过的错误判断。保留原始数字、出处和版本。只改变一个会影响结论的条件。分别覆盖组件提速、回放层级、通信路径和环境错误。
2. 单独保存评审答案。评审先标记支持、反驳或证据不足。再核对来源、关键行是否进入上下文、结论范围与下一项判别实验。版本、正确性与计时口径可做硬检查。归因与实验设计用同一 rubric 人审。
3. 第一轮先记基线。记录危险误判、正确判断被误拦、引证缺失与人工修正次数。把主动查找、读数和审阅时间与等待时间分开。至少在每个案例保留正确结论的同时，拦住该案例的指定错误。记录分母和不确定性。六个样本只用于发现问题。
4. 下一轮用新的 shape、PR 或部署拓扑检查迁移。同一个原始案例的变体放在同一侧。比较前固定判分口径。单人重复评估时用匹配的变体交替安排，避免第二次做同一题时记住答案。

如果只给证据包就降低遗漏和人工返工，优先完善索引。如果只增加硬检查才减少错误，优先实现相应工具。若定位正确但关键行未进入上下文，先验证范围读取或结构化提取工具。若固定步骤经常卡在需要重新调查的分支，用有状态的工作流与开放式 harness 比较。如果信息和工具齐备后仍有可稳定标注的重复判断错误，再比较技能、人工示范和 SFT。若证据齐备后仍有危险误判且硬检查无效，先记录错误类别，再用人工示范做小样本对照。若两个方案的错误相同而人工成本不同，先以匹配变体重复，检查差异能否重现。

对照依据见 [OpenScholar 与 BrowseComp-Plus 的证据直给、定位和全文读取](sources/retrieval-followup.md)。压缩恢复和多 Agent 对照可用 [TRACE 与分工实验](sources/harness-followup.md) 中的控制方法。

以上是验证设计。现有日志可以支持案例范围，暂时没有方案效果和人工节省的实测。
