# 哪些 AI Infra 工作判断值得改变

## 研究验收

每项课程方法都要回答一个工作问题。给出当时可用的证据、原有做法、建议改变的动作，以及什么观察会使工程师改回去。四个原始案例是调查入口。新增案例回查实验中的取舍、失败和交付判断。优先级依据是决策后果、重复出现的迹象、改进是否可测、以及现有工具能覆盖多少。没有可比的人工作时或线上任务分布，当前排序用于决定**先验证什么**。

## 沿工作过程找机会

| 工作环节 | 当时的做法与观测 | 可改变的动作 | 最便宜的区分办法与失误代价 |
|---|---|---|---|
| 选题、定优先级 | DeepInfer 先让 NVLink 路径可运行。真实权重 sweep 改了上下文和并发，接受率几乎固定。HW3 三个 prompt 的收益方向也不同。 | 先锁定目标指标和代表性请求，再选调通信路径、fetch、推测验证还是排队。让候选各自声明会影响哪些请求。 | 用已保存的请求数据检查现有切片是否覆盖低接受、尾延迟和压力点。若没有，先选能区分假设的切片。把固定合成请求当作总体会误排优化方向。 [DeepInfer workload](cases/07-workload-choice.md) · [独立 HW3 核查](cases/08-speculation-acceptance.md) |
| 定位瓶颈 | vLLM 按轮次还原访问、预算和 token 配额。DeepInfer 分段计时曾给出组件量级，重叠与依赖未由这些时间确定。 | 找第一个状态分歧或等待边。先明确竞争解释，再决定加哪项状态读数、事件或受控干预。 | 隐藏结局，比较是否用现有证据排掉预算不足等解释。对组件 trace，让建议写清下一条依赖证据。误判会把优化预算花在并行路径上。 [vLLM](cases/02-vllm-scheduler.md) · [DeepInfer profiling](cases/03-deepinfer-profiling.md) |
| 生成和筛选候选 | GEMM 从 PC 与 SASS 提出 TMEM base hoist。DeepInfer 分别试 fused、prefetch 和组合。 | 用源码、硬件和 workload 各提出不同机制假设。预先写可区分的预测，先排掉编译、拓扑或容量不满足的候选。先区分候选不够与已有候选选错。 | 固定证据和预算，盲评手工与模型列出的候选是否有新的可行机制，及筛选后第一项能否判别。候选越多，编译和测量成本越高。 [GEMM](cases/05-kernel-search.md) · [L20](notes/search-and-next-experiment.md) |
| 设计实验 | hoist 删除重复 LDS，但同卡顺序影响大于平均差。PDL 的总体均值掩盖重复出现的形状退化。 | 先做 A/A 估计分辨率。固定工作量并交错执行 A/B，按 shape 和指标验收。必要时复测独立分配。 | 在原始计时、分组和 seed 上重算一个对照，检查下一项实验是否能消除主要混淆。误判会保留不稳定或局部退化的变更。 [GEMM](cases/05-kernel-search.md) · [MSA](cases/04-minimax-msa-pdl.md) |
| 执行和恢复 | 云调用遇到观察器超时、无容器终态、设备检查、容量断言和镜像内导入失败。 | 先读同一 call 的服务端状态。记录首个失败阶段。能在相同镜像和架构下先查的条件尽量前置。 | 用历史日志回放，测是否误重提、把排队当成代码失败、把正常进程取消。严重错误包括重复花费和中止有效运行。 [框架执行](cases/06-framework-delivery.md) |
| 按反馈调整 | 首测优势、接受率过窄、组件变化与总时延矛盾，都曾使原计划失去判别力。 | 用当前证据更新优先级。明确何时暂停优化、补测量、换负载、换机制或停止。 | 给回放增加一个真实新观察，检查能否据此改变下一步。需要注明理由、相反结果的后续动作及不可逆操作。见下文。 |
| 验证与交付 | vLLM 的教学回放与上游回归断言各有证明范围。DeepInfer 的本地原型在未合入的社区 PR 上。 | 提交前固定版本、正确性、默认路径、支持拓扑及适用区间。按变更范围选状态回归、性能基准或服务测量。 | 对同一变更做盲审，评估关键缺项、误拦和修订时间。用户实际 reviewer 返工资料待补。错误归属或夸大适用范围会误导维护者。 [vLLM](cases/02-vllm-scheduler.md) · [DeepInfer 交付](cases/06-framework-delivery.md) |

训练系统的分支见 [CS336 DDP/FSDP](cases/09-distributed-training.md)。原始 trace 里已存在的 GPU 事件可用于修关联。独立训练轨迹的数值分歧需要另一项实验。两者与推理服务的任务和实现独立。

## 机会比较

| 机会 | 预期价值与所需输入 | 当前依据 | 排序改变的条件 |
|---|---|---|---|
| 观测后改选下一项实验 | 提前淘汰无判别力的运行。需要目标、当前候选、最后一项原始观测、成本和可用工具。 | GEMM 的 A/A 分叉、DeepInfer 的接受率与依赖分叉、vLLM 的状态解释、HW3 的正确性门槛提供多种可回放情形。每类历史样本仍少。 | 工程师用现有流程已经稳定选到同一动作，或固定规则覆盖几乎所有有害错误时，优先级转到更常发生的执行或 workload 工作。 |
| 代表性 workload 和对照设计 | 直接改变服务优化排序。需要工作量分布、到达过程、指标目标、内容或接受率。 | DeepInfer 三种形状未覆盖接受率差异。HW3 离线数据及 DeepInfer 作者的容量区间说明负载条件会改变方向。无代表性线上序列。 | 若当前主要任务是服务部署且可访问目标负载，或目标指标对该差异高度敏感，先验证负载与对照。若没有必要输入，先验证请求捕获和回放。 [现成回放及范围](sources/workload-decisions.md) |
| 提交前预检和可恢复执行 | 减少重提、错误中止或等待后才发现输入问题。需要稳定调用 ID、阶段结果、镜像和预算。 | 有终态和实际恢复原调用的记录。DeepInfer 的两篇新案例是同一证据家族。没有多项目频次或节省记录。 | 若近几轮项目反复花时间在同类云端故障，且状态机能抓到大多数关键分支，先做此项。 |
| 生成更好的优化候选 | 发现人和固定规则都没有想到的可行机制。需要可执行候选、前置条件及可靠评价。 | GEMM、DeepInfer、HW3 有不同假设和淘汰过程。无法测量未发现候选，且不稳定评价会影响筛选。 | 在固定有效筛选器下，新增候选多次胜过原有候选，并有足够预算复测时，提升优先级。 [搜索方法](notes/search-and-next-experiment.md) |
| 证据复核和交付 | 减少写错适用范围、丢失负结果和来回复核。需要原始产物、目标读者和交付口径。 | 四个初始案例均支持该问题存在。硬规则有可比输入。缺用户实际审查返工和人工作时。 | 若读证据占主要工时，或下游审查反复卡在可自动核查的缺项，先做索引、提取或复核。 [原方案](DECISIONS.md) |

先验证**收到新证据后，能否改选下一项实验**。一项会失去判别力的实验可能花掉一次 GPU 分配，也可能把后续候选排错。这个问题连接选题、诊断、候选、测量与执行。它能与证据复核、固定流程和开放调查共用同一个验收动作。当前缺少各环节的发生率。排序在独立回放和真实任务基线后可以改变。

NVIDIA Dynamo v1.6.1 已有冻结 workload 和基线、选候选、审核、测量和停止的优化闭环。服务调优的固定流程基线应包含可用的现成步骤，比较新增能力对目标引擎有没有价值。Dynamo 文档中的部署与 benchmark 入口主要面向自身栈。DeepInfer 的 Engram 依赖、B300 的 PC 对应和其它框架的状态需要单独验证。 [Dynamo Optimize Loop](https://github.com/ai-dynamo/dynamo/blob/v1.6.1/agent-docs/guides/optimization/optimize-loop.md) · [来源和接入边界](sources/workload-decisions.md)

## 最小验证

先用现有证据做一次离线决策回放。每题在作出历史决定之前截断。冻结输入中的目标、设备、源码、原始日志、候选和可运行操作。随后加入一条当时可获得的新观测。参与者先后各答一次，写明首选动作、最小所需证据、两种可能结果对应的动作、时间和 GPU 成本。隔离工具可访问的当时材料，放入代表事后资料的测试文件，核实两组都无法读取。GEMM 顺序效应、DeepInfer 运行中断和 vLLM 逐轮状态用于试判分。HW3 和 CS336 也已用于研究，后续需要另选未参与设计的任务家族或运行批次。

1. 在同样输入和允许工具下，比较现有人工作法、固定检查流程、同模型用固定流程、以及同模型可分支调查。先用同一批原始证据；若失败集中在找文件或提取读数，再单独做给出处与直接给片段的对照。固定流程允许根据工具可用性与成本选择分支。动态版本用同样的证据权限、用时和操作预算。用同一个 GEMM 决策前缀比较 A/A 随手可做与需另排队两种条件。分别报告行动错误、主动时间和 GPU 成本。 [L5 成本对照与 L15 隔离核查](coverage/search-2026-11-13.md#能改变排序的既有讲次资料)
2. 至少覆盖一个应改选、一个应保持、一个证据不足需低成本复核的决定。按原始观察判分，接受能区分同一组竞争解释的不同动作。记录目标不符、使用不可比证据、无效试验、危险重提、可预期的 GPU 成本和人工主动用时。单独报告候选里是否已有可行下一步、以及最终选中了什么。
3. 判分之前由两位熟悉工作的评审独立检查。硬约束包括输出正确性、比较条件一致、重复提交与现有权限。关键错误按案例预先定义。例如 A/B 信号随顺序反转时继续加 kernel 候选，或原调用存活时重复排队。可行的预检和可行的定位动作都允许。样本小的时候逐题报告结果。
4. 若固定流程已经避免相同错误，且人用时更低，先保留固定流程。若证据直给带来同等改善，优先做索引或提取。若动态方案在独立样本中减少有害决策，且成本足以抵消人工时间和潜在无效运行，再扩展可分支的工作流或 harness。若方向判断已可靠但故障恢复仍不可靠，转向运行状态。若主要错误发生在目标和切片定义，转向 workload 选择。若动态方案与现有基线均无改善，暂停当前方向。

## 从改进动作选择产物

| 看到的限制 | 可先验证的产物 |
|---|---|
| 资料齐全，但经常找错运行、版本和分母 | 证据索引。若字段固定，另测小脚本能否在输入阶段拦错。 |
| 已知约束或失败分支经常遗漏 | 可复用工具或固定工作流。用回放验证断点恢复和错误分类。 |
| 相同证据和工具下，下一步仍取决于新机制和新观察 | 先比较同模型固定与可分支流程。实测显示收益后再决定是否需要 Agent 或 harness。 |
| 不知道方案能否改善决策 | 小评估集。用早期案例试判分，按项目、运行批次、PR 或 kernel 家族留出真正未参与设计的任务。 |
| 充分证据、工具和规则下，模型仍反复犯同类错误 | 先做人工核验的决策示范，检查独立评审能否一致标注。用同模型做带示范的上下文对照。若反复出现且标签稳定，再考虑 SFT。训练用前缀、目标动作、原始证据与边界。按任务家族隔离留出，比较工具齐备的基础模型、示范与训练模型。 |

当前研究输出是工作机会和试验设计。尚未测得辅助方案的节省、覆盖率或线上收益。 [覆盖与续做](PROGRESS.md)
