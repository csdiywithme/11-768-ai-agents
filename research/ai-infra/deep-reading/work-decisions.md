# 阅读结果怎样改变 AI Infra 工作

以现有人工做法和可复用工具为基线。以下动作来自课程方法、外部原文和已有案例的对照，属于可验证假设。案例已用于研究。用后续独立项目、PR 或运行批次验证实际收益。

| 工作问题 | 阅读后会改变的判断或动作 | 最小对照与反例 |
|---|---|---|
| 选哪段 workload，先动哪里 | 先列出会翻转优化排序的条件。DeepInfer 的接受率问题要保留实际内容、模板、draft/target 版本和任务阶段。路由与 KV 可以先用保留到达和 prefix 的请求图。记录队列、I/O、被覆盖与未覆盖的耗时。 | 同一批请求比较合成形状和保真输入。再切长短、冷热、负载压力。两种回放对缓存一致却对接受率排序相反时，优先补内容与分桶。用现有 AIPerf 或 llm-d harness 作为基线。 [重放边界](site-followups.md) · [TraceSpec](infra-research-followup.md) |
| 下一条 profile 应查什么 | 先找会改变动作的竞争解释。例如 vLLM 的 RUNNING、被访问、拿到预算、实际执行是四步。GPU 计时先确定当前差异大于测量波动，才值得归因到 PC、SASS、带宽或同步。 | 同一状态前缀要求选择一项观测并预测相反结果的动作。保留 A/A、匹配 A/B 和无 profiler 计时。若交错后差异翻转，先查测量顺序。若 C 合法延后，继续查真正发生退化的请求。 [调度和测量](serving-diagnostics.md) · [算子观测](gpu-performance.md) |
| 是否值得增加候选和 GPU 预算 | 分开统计找到有效候选的比例、从中选对的比例和独立复测是否成立。让模型从实验反馈提出机制不同的候选，而非对一个最快候选继续做同类小改。 | 同预算比较人工、参数矩阵、模型多候选和按证据改方向。保留正确但慢、未编译、跨形状退化和工具不可用。若候选覆盖变好但选中结果未变，先修评分。若独立验证未过，撤销收益判断。 [L20 搜索](search-course-readings.md) · [KernelEvolve、KernelBench 与 AIDE](infra-research-followup.md) |
| 超时后要等、接回还是重跑 | 先把观察器、调用、容器、产物分成可核对状态。上下文压缩前保留当前目标、不可逆约束、原 run ID、实际已完成的证据与下一步。 | 在同一决策点模拟 stream 丢失、运行中断、作业继续、产物迟到和用户改约束。记重复花费、错过产物、恢复时间和人工接管。若固定状态检查已覆盖主要错误，先评小工具。 [OpenHands 运行例子](search-11.md) · [压缩与状态](context-memory-03.md) · [编排与恢复](orchestration-02.md) |
| 如何避免评测高分掩盖真实失败 | 检查题目是否可达、oracle 是否测试目标、是否有等价实现以及环境是否对齐。任务成功、决策正确、证据可复核、主动时间和返工独立记录。 | 在留出题用合法替代实现、已知负例和环境失败测试评分。若静态规则与人评有分歧，回到原始状态和目标口径。公开 benchmark 的历史分数只作同条件参考。 [SWE-bench 与 τ-bench 审计](evaluation-validity.md) · [真实人机协作](human-work.md) · [人工时间测量](external-evidence-02.md) |
| 何时需要工作流、Agent 或训练数据 | 日志、版本或事实缺失时先改善输入。确定动作可由同一字段条件决定时先评脚本。需要综合新证据分叉时，再比较固定流程和可分支的 Agent/harness。只有目标行为反复出错且标签可复核时，才进入示范或训练对照。 | 固定模型、可见材料、工具与预算，依次增加证据、机械检查、动态选择和示范。给错误前缀而非只给胜者。用两个评审先检查标注一致和合法多解。训练前后都要通过真实工作用例与跨项目留出。 [同证据上的迁移](../OPPORTUNITIES.md) · [蒸馏与错误前缀](distillation.md) · [数据合同](sft-data.md) |

## 哪些信息会改变产物排序

- 若候选大多在硬件、工作负载或测量条件上失效，先改善预检和评价。若评价稳定且人和固定搜索始终漏掉有价值的候选，再增加搜索能力。
- 若问题在运行恢复或产物关联，先保留可核对的外部状态。能够找回正确 run 并恢复的固定流程已是强基线。需要跨仓调查、重规划或人工接管时再比较 harness。
- 若给齐证据后所有路线都改进，先找成本最低的提取和索引做法。若只在某个模型反复出现的决策错误有稳定标签，再考虑把前缀和专家动作做成评估、示范或 SFT 数据。
- 若没有真实 workload 或工作时间样本，以上仍不能确定最值得投入的方向。把每项验证的输入、成本和影响范围带入真实工作排序。 [现有案例与最小验证](../OPPORTUNITIES.md)
