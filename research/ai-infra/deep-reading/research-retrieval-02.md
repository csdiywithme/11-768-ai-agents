### `https://www.nature.com/articles/s41586-025-10072-4`

- 原文：[OpenScholar，Nature 正式 PDF](https://www.nature.com/articles/s41586-025-10072-4.pdf)
- 范围：Nature 650，857–863，2026-02-04 在线发表。重点图 1、表 1–3、Ablations and analysis、Methods 的推理流程、Extended Data Table 2。文章 HTML 的网页工具访问触发登录跳转。正文通过同出版社的正式 PDF 核对。
- 机制与证据：45M 开放论文语料与其他检索入口结合，重排片段后写初稿，按反馈补查并检查引用。Scholar-CS 的正式版扩展表显示，OS-8B 完整系统的 rubric accuracy／引用 F1 为 51.1／47.9，去重排为 49.6／28.2，去反馈为 50.5／41.4。检索分项另在关闭反馈和引用核查、同一 top-15 reranker 下测量，普通网页 45.9／12.6，三个检索源合用 49.6／47.6。专家偏好研究使用 108 道 Scholar-Multi 问题，输出长度和引用数量亦有差异。
- 工程动作与反证：对同一组框架问题固定候选语料、模型与篇幅，分别打开术语重排、反馈补查和声明核查。对每次改动记录增加了哪个可检验事实，引用是否支持实际硬件和版本。若反馈主要扩大篇幅、重述已有证据或拉入不匹配版本，减少反馈轮数，先改善检索与重排。

### `arxiv:2505.14963`

- 原文：[MedBrowseComp，arXiv v1](https://arxiv.org/html/2505.14963v1)
- 范围：§§3–4、5.1，表 1–3 的基准设计、样本选择、字段抽取和系统误差。只迁移检索评估。

- 工程动作与反证：做 profiler 工单时分开测定位正确报告、提取正确 kernel ID、再跳到对应源码。给同名符号和不同 rank 的合理干扰。比较 UI、结构化 API 和固定文件解析。如果找到同名条目仍频繁错配，增强实体核对和原始字段校验，再改导航。

### `arxiv:2509.13305`

- 原文：[WebSailor-V2，arXiv v1](https://arxiv.org/html/2509.13305v1)
- 范围：§§2–4、5.1–5.4，表 1、图 2、5–6。核对数据构造、SFT/RL 阶段和工具预算。
- 机制与证据：用网页事实和实体构建高密度关系图，通过随机游走选择子图，把不同角色的节点变为待查目标。用合成题和检索轨迹做 SFT，另用模拟和真实环境做 RL。表 1 的 30B-A3B 在 BrowseComp-EN 上从 SFT 24.4 到 RL 35.3，BrowseComp-ZH 从 28.3 到 44.1。该比较包含数据与训练阶段变化。部分外部系统结果引用原论文或网页测评。
- 工程动作与反证：从公开 PR、release、源文件、profiler 计数器关系倒推查询题，故意加入同名旧实现或硬件版本干扰。让标注员检查每个关系是否有独立原件，测试给定事实后能否找到唯一结论。若合成线索只让题目变绕，或可凭仓库名猜出答案，换成能改变诊断动作的约束。

### `arxiv:2505.22648`

- 原文：[WebDancer，arXiv v3](https://arxiv.org/html/2505.22648v3)
- 范围：§§2.1–2.2、3.1–3.2、4–5、附录 A。核对漏斗筛选、表 3 及重复试验指标。
- 机制与证据：crawlQA 从有结构的公开来源构造问题，e2hQA 通过替换实体线索增加检索步骤。轨迹依次检查格式、答案和质量，再进入 SFT/RL。表 3 的 Qwen2.5-7B 用短示范和长示范时 Pass@3 为 33.98 和 35.92，但无效比例从 0.65% 到 21.36%，Cons@3 从 22.33 到 21.00。结论也受网页返回变化影响。
- 工程动作与反证：同一回放同时留短决策记录与长诊断记录，用相同轨迹任务和工具接口训练或提示。观察能否使用、重复成功比例、无效调用和执行时间。若长轨迹只提升多采样的最好结果，但常规执行失败上升，优先改善短调用或记录证据。

### `arxiv:2509.13310`

- 原文：[Scaling Agents via Continual Pre-training，arXiv v1](https://arxiv.org/html/2509.13310v1)
- 范围：§§2.1–2.3、3.3–3.6，表 3–5 和图 6。核对阶段上下文、数据量和不同 SFT 数据比较。
- 机制与证据：FAS 在合成场景生成计划和动作；HAS 在旧轨迹状态生成备选动作，再建立选择监督，备选本身未实际执行。表 3 同为 SFT-B，Qwen3-30B-A3B-Base 与 AgentFounder-30B-Base 的 BrowseComp-en 为 28.6 和 39.9，GAIA 为 71.8 和 72.8。表 5 同为 50B 训练 token，加入 HAS 后 GAIA Pass@1 从 72.8 降为 69.9，Pass@3 从 80.6 到 82.5。
- 工程动作与反证：以已核 profiler 状态生成几个可选下一步，给每个选项标明预期改变的观测，再运行少量关键分支。比较单次决策与候选多样性。若评分更喜欢专家措辞但真实分支不能排除任何假设，保留候选作为建议，暂停把它们作训练标签。论文规模本身不能给小样本任务定预算。

### `arxiv:2503.09516`

- 原文：[Search-R1，arXiv v5](https://arxiv.org/html/2503.09516v5)
- 范围：§§3.1–3.4、4.1–4.4、5.1–5.4，表 2–4、附录 J 的失败分析。
- 机制与证据：模型在轨迹中生成查询，环境把搜索片段作为观察插回。PPO 或 GRPO 的策略损失对外部返回 token 做 mask。训练奖励为抽取短答案后的 exact match。表 4 的 Qwen2.5-7B-base、PPO、2018 Wikipedia、E5 设置，在七项 QA 上平均 EM 从无 mask 的 0.343 到有 mask 的 0.431。测试中也有被相邻但不相关片段带偏的案例。
- 工程动作与反证：保存生成动作和外部日志各自的边界。训练只在应由模型生成的决策处计相应策略损失。对任务完成判定还要检查命令是否成功、是否提取正确观测、是否保留原始证据。如果最终字段匹配但调用读错 baseline，按工程判定为失败。
