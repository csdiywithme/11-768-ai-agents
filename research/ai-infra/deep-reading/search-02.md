# L06、L20 深读 · 代码评估与基于反馈的改进

本批核查八项登记来源的正文选段。用可执行结果审查验收方式，再检查定位、反馈和复用能否改变下一步。所有 AI Infra 对照都是从原方法推导的验证建议。

### `arxiv:2107.03374v2`

- 原文：[Evaluating Large Language Models Trained on Code](https://arxiv.org/pdf/2107.03374v2)
- 范围：arXiv v2。细读 §§2.1–2.3、3.2–3.3、§4 中的选样实验和 §6 的模型失败；核对 Figure 2 和 pass@k 估计式。未阅读全部 35 页与附录。
- 机制：HumanEval 的 164 道题从 docstring 生成函数，用单元测试判功能正确性。每题有 n 个候选与 c 个通过时，文中用 1 减去从 n 个候选中取 k 个且全失败的组合比例，再跨题平均。这个估计衡量有无可通过的候选，交付一个结果还需独立的选样办法。§3.3 中，单候选和大候选池的最佳采样温度可不同。
- 改变的动作：在 CUDA/Triton 优化助手中，先报告同一预算内生成了多少独立候选、多少通过参考测试、选择器实际选中了哪个。性能提升采用同 workload 和硬件的计时，只给满足数值契约的候选排序。每题先计算再汇总，保留难题和没有任何通过样本的题。
- 推翻条件：先冻结候选池，用同一组有效样本比较参考测试覆盖、最终选中率、wall time 和 GPU 分配。如果扩大样本池只增加理想覆盖，实际选中或净收益没有变化，改进验证或选择环节。若测试覆盖变化导致候选排序颠倒，先核验 oracle。

### `arxiv:2303.11366`

- 原文：[Reflexion: Language Agents with Verbal Reinforcement Learning](https://arxiv.org/html/2303.11366v4)
- 范围：arXiv v4，NeurIPS 2023。细读 §3 的 Actor、Evaluator、Self-Reflection 与 memory，§§4.1–4.3 的任务和编程消融，以及 §5。未复跑原实验。
- 机制：让评分或失败轨迹产生短反思，放入有容量限制的记忆，下一轮使用同样的策略模型继续。编程场景用模型生成测试和执行反馈。Table 2 记录内部测试都通过时最终提交错误的比例，MBPP Python 为 16.3%，HumanEval Python 为 1.4%。HumanEval Rust 的 50 道困难题中，省略测试的反思版为 52%，低于文中 60% 基线。
- 改变的动作：每次分析、编译或执行失败后，存一条带原始证据的短记录，写明预期、实际、判断与下一步。遇到工具异常，先把未执行、输入不符和真正的候选失败分开。先用独立预检或可重放的原始日志校正反思，再将它带入下一次。
- 推翻条件：固定模型与读取权限，比较原始失败日志、日志加经核验的反思、日志加模型自由反思。若反思更常把计时噪声写成根因、让后续越过正确性闸门，或未降低重复失败，使用可检查的原始记录。

### `arxiv:2310.06770`

- 原文：[SWE-bench: Can Language Models Resolve Real-World GitHub Issues?](https://arxiv.org/html/2310.06770v3)
- 范围：arXiv v3。细读 §§2.1–2.4、§§4.1–5.1、§7 的相关段落，附录 A.2–A.4 的环境构造及验证。此处使用原始 SWE-bench 的口径。
- 机制：从真实 issue 和已合并 PR 建 2,294 题，锁定改动前代码和环境。用 fail-to-pass 测目标问题，用 pass-to-pass 检查既有行为。验证用报告当时的信息，排除提前泄露修法的后续评论。论文中 Claude 2 用 BM25 时是 1.96%，给实际改动文件的 oracle 是 4.8%，再把范围缩至实际改动行附近为 5.9%。后两组依赖事后定位，只能当诊断上界。
- 改变的动作：给 vLLM 类问题做离线回放时，锁定 issue 当时的 commit、依赖、运行命令和输入。事后 PR 放在评审侧。调度修复要同时检查触发问题的序列状态变化、原可通过的请求路径和无关改动。另留一组同机制但来自其它版本或项目的例子。
- 推翻条件：若复现前后的结果由依赖或时间漂移决定，或无关补丁也能通过，改写测试和固定环境后再比较助手。若给正确文件后仍常失败，可继续对照更精确证据和工具，不能把失败全记为检索问题。

### `arxiv:2405.15793`

- 原文：[SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering](https://arxiv.org/html/2405.15793v3)
- 范围：arXiv v3。细读 §§2–3、§4、§§5.1–5.2、§7 和附录 A.3 的编辑反馈。核对 Tables 1、3。
- 机制：把代码导航、编辑和执行设计成适合模型消费的动作。文件阅读返回路径、行号和有限窗口。改动触发主要 lint 错误时，恢复改动前文本并返回错误及前后差异。主实验中 GPT-4 Turbo 完整集解决 12.47%。Lite 的同模型表中 SWE-agent 解决 18.0%，仅用 shell 的对照为 11.0%，去掉演示后为 7.33%。这组结果以特定 Python 题集、模型和成本上限为条件。
- 改变的动作：若助手反复开错目录、在同一源码位置绕圈，或截错 profiler 日志，先让现有工具返回明确范围和实际输出。输入写明 commit、运行和文件标识，结果把原始证据、截断和失败原因一起返回。可回滚的局部编辑可以先过编译或静态检查，再交给完整执行。
- 推翻条件：在相同预算与同一复现路径上，对比普通 shell、结构化工具输出和人工基线。若减少的无效调用无法抵消维护成本，或模型因窗口太窄遗漏跨文件依赖，保留通用工具并只改造成有稳定错误记录的接口。

### `arxiv:2305.01210`

- 原文：[Is Your Code Generated by ChatGPT Really Correct?](https://arxiv.org/html/2305.01210v3)
- 范围：arXiv v3。细读 §§2.1–2.3、§3 的主结果、参考实现与测试缩减实验，§5。核对 Table 2 和 Figure 2。
- 机制：EvalPlus 先用模型辅助产生种子，再按类型变异输入。用输入契约过滤无效样例，以参考实现做差分测试。缩减测试时按分支覆盖、可区分的变体和已知错误候选等目标做集合覆盖。HumanEval+ 的用例规模约为原集 80 倍，26 个模型的部分 pass@k 下调，部分排序翻转。作者也复核并重写了有问题的参考实现。
- 改变的动作：在验证新 kernel 前，列明 dtype、shape、stride、layout、mask 与容差契约，建立覆盖边缘形状的正确性样例。先用历史上出现过的失败和人为变体选择便宜的 smoke 子集，再保留完整套件用于最终确认。错误输入单列，参考路径也做独立检查。
- 推翻条件：若缩减后的套件漏掉新版本或另一硬件特有的错误，扩大正式验收覆盖。若错误集中在参考实现共享的假设，先引入独立算子实现或不变量。用历史错误和留出的新型错误分别测预检代价与漏检率。

### `arxiv:2406.12952`

- 原文：[SWT-Bench: Testing and Validating Real-World Bug-Fixes with Code Agents](https://arxiv.org/html/2406.12952v3)
- 范围：arXiv v3。细读 §§3.1–3.3、§§4.1–4.4、§§5.1–5.4 相关正文及结论。核对 Tables 2、3 和测试过滤实验。
- 机制：专门评估能否先写出复现问题的测试。测试在改动前失败，在参考补丁后通过，才计为 fail-to-pass。作者还看改动行覆盖和错误类别。剔除原套件不稳定或无法执行的案例后，共 1,983 个任务，Lite 为 276 个。论文中用自生成测试筛修复，报告精度 47.8%，召回率只有 20%。
- 改变的动作：把 vLLM 的问题复现交给独立流程。对调度和缓存问题，先要求测试在原 commit 因同一目标断言失败，在修复 commit 通过，并记录原始状态。对性能问题，先验证 A/A 的稳定性，再确定 workload 和预先约定的度量。生成测试可以降低审核负担，保留人工处理被误挡的候选。
- 推翻条件：若把无关错误也算复现，或测试只能因环境差异失败，停止使用该过滤。逐例比较工程师的有效候选、测试筛掉的有效候选、筛掉的无效候选和人工复核时间。保留召回损失与精度改善，按目标决定用途。

### `arxiv:2401.15963`

- 原文：[NoFunEval: Funny How Code LMs Falter on Requirements Beyond Functional Correctness](https://arxiv.org/html/2401.15963v3)
- 范围：arXiv v3。细读 §§2.1–2.4、§3、§§4.1–4.5 和 §6。核对运行时任务、latency/resource 分类与 DiffBLEU 的适用范围。
- 机制：评估性能、资源等非功能目标时，给编辑和辨别两种任务。运行时子集由 113 对有通过测试且经确认的快慢程序组成，以 25 次重复测量计算相对速度，遇到错误或减速按返回原程序计。面向异构平台的 latency/resource 子集使用 DiffBLEU 比改动相似度，属于替代量。能改好代码和能从一对候选中认出更好的代码是两种经验上可分开的能力。
- 改变的动作：把「改出更快的算子」和「判断哪个结果可信」分成不同评估。第一项以正确性和独立计时验收。第二项给成对源码、trace 与指标，随机交换顺序，让模型指出依据和需要补的观测。没有目标硬件时，报告能否解释机制和设计对照，保留尚未获得的性能数值。
- 推翻条件：若文本相似度和实机排名不同，去掉相似度验收。若交换候选顺序后选择大变，或模型解释常引用不可比的 benchmark，先核查证据来源，继续比较人工和固定检查流程。

### `arxiv:2602.04837v1`

- 原文：[Group-Evolving Agents: Open-Ended Self-Improvement via Experience Sharing](https://arxiv.org/html/2602.04837v1)
- 范围：arXiv v1。细读 §§3.1–3.2、§§4.1–4.3、§§5.1–5.4、§6 的边界。核对 Algorithms 1–2、Table 1 和分阶段评估。
- 机制：存档候选 Agent 版本。按成绩与任务成功向量定义的差异选一组父代。各分支共享执行记录、失败补丁和结果后，仍分别形成新版本。评估用小集排除不能运行的版本，再逐级扩大，两个主要实验基准为 SWE-bench Verified 和 Polyglot。其 SWE-bench Verified 选中结果 71.0%，隔离分支的 DGM 式对照 56.7%。论文匹配演化产物数量和模型安排。它同时记录累计代码修改和高计算代价。
- 改变的动作：如果并行查 trace、依赖和 workload，先用统一字段交接原始证据、排除项和仍能执行的下一步，让分支可借用有效发现。发现可以迁移的工具或规则时，先单独评估该改动，再在独立历史案例上复测。
- 推翻条件：与同预算的单流程、分支各自调查、分支共享摘要做对照。若共享让错误前提传播，输出大幅变长但无实质增益，或同个问题被重复验证，减少共享频率，保留原始证据并简化流程。该论文的演化结果不能证明本地任务应改造 harness。

## 对本地工作比较的影响

对 vLLM 和类似框架，先用真实的旧新 commit 加代表性测试确认首个状态分歧，再分别测定位、复现、修复和交付是否改善。对 kernel，把测试或编译错误、已通过正确性的性能候选和没有可比数据的运行分别记账。对模型辅助的调查，在相同原始证据和资源限制下，比较结构化工具反馈、独立多候选筛选和经核验的反思。用是否选中能区分假设的动作验收，保留误拦与漏检。
