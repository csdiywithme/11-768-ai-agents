### `arxiv:2506.07976`

- 原文：[Thinking vs. Doing v2](https://arxiv.org/html/2506.07976v2)
- 范围：§§3、4.1–4.2、5.1–5.2、6.1–6.3、附录 D.4 与 E.4–E.7。核对 Figure 2 的总 token 口径、复查和动作投票。
- **方法。** 把预算分给更长的单步推理、每步多个动作候选，或更多与环境交互的步骤。后者可获得新信息。论文先用强制复查做受控对照，再用逐步增加最大交互长度的训练课程。
- **证据与边界。** Figure 2 的 WebArena 对照中，额外交互在匹配每轨迹 token 预算时优于另两种增量。候选设置用每步 3、5 或 7 个动作的多数投票。重复要求复查有时使已对的答案变错，训练后的任务还出现反复重置与识别条件错误却仍提交的例子。这里未匹配外部工具时间、排队与副作用。
- **工作动作。** 面对两种机制解释时，先判断有无可区分的只读证据。比如先查已存在 trace 的依赖和工作量，再决定是否换候选。一次新的读数没有改变解释时，应按停止条件收束。
- **验证。** 给同样决策前缀和总成本，比较多一次只读观测、更多分析 token 和多候选。按下一步选择与错误改选分别评分。若新的读数噪声太大或成本更高，减少访问并明确留下不确定性。

### `arxiv:2602.16699`

- 原文：[Calibrate-Then-Act v3](https://arxiv.org/html/2602.16699v3)
- 范围：§§2–6、附录 A、C、D。核对 FileReading 的先验来源、成本比例、Table 3–5 和准确率与折扣奖励差异。
- **方法。** 用可估计的先验表示未知状态，让模型据成本选择继续观察或直接行动。FileReading 的受控任务使用关于文件格式的经验先验，对比单元测试与代码执行相对成本。先验可显式给提示，也可以参与训练。
- **证据与边界。** Table 4 的四个成本条件平均中，CTA-Prompted 比常规 Prompted 的折扣奖励从 0.229 升到 0.240，准确率从 0.958 降到 0.945。CTA-RL 的奖励为 0.268，RL 对照为 0.259。训练和提示配置中的先验可见性有差异。附录说明真实任务可能有更多变量与更嘈杂的观测。
- **工作动作。** 当同架构编译预检、已有 A/A 和新排 GPU 的成本不同时，给固定流程和模型都提供预计成本、现有信息及数据新鲜度。用条件决策确定先查哪项。历史经验先保留样本条件。
- **验证。** 用同一个 GEMM 决策前缀修改 A/A 已可用与必须排队、以及失败后返工的代价。分别统计错误动作、保住硬门槛、人工主动时间和 GPU 成本。若成本分支可以写成少量规则，先用规则作为基线。

### `arxiv:2606.01533`

- 原文：[Multi-Agent Computer Use，MACU v1](https://arxiv.org/html/2606.01533v1)
- 范围：§§3、4.1–4.3 与附录 A、B。核对 Table 2 重规划、pass@k 对照和 Figure 5 并发。
- **方法。** Manager 创建任务 DAG，管理子任务依赖并在运行时改图。子 Agent 使用隔离环境，可从前驱环境状态继续。并发度和重规划次数都受预算约束。
- **证据与边界。** 36 项 OSWorld 小子集用 Qwen3.5-4B Worker。无计划、只写初始 DAG、重规划预算为 5、10 的成功率为 25.0%、27.8%、47.2%、58.3%。Odysseys 45 个简单任务中，并发 1 到 4 的中位时长从 25.4 降到 7.9 分钟。论文的时间口径排除了推理开销，适用范围是该设置。pass@k 需要已知评估器才能提前停。
- **工作动作。** 并行核对独立源码、日志和文档。在需要同一 baseline、相同拓扑或同一个 run ID 时，先合并并锁定条件。只在新观察改变依赖或后续选择时更新任务图。
- **验证。** 比较单流程、固定依赖图和可修订图。使用同样工具与原始证据，分别记录研究、模型、等待、重复读数和人工合并的用时。若并发带来的主要收益只在可静态分组的任务出现，优先固定分组。

### `arxiv:2205.11916`

- 范围：§§3.1、4、5、6，核对两阶段提示、Table 1 结果、Table 4 提示变体与附录错误类型。
- **方法。** 用零样本指令诱导模型输出中间步骤，再用第二阶段提示抽取答案。无需给任务的已解样例。
- **证据与边界。** 特定模型和解码设置下，MultiArith 从 17.7% 到 78.7%，GSM8K 从 10.4% 到 40.7%。提示变体改变效果。生成中间说明不会自动验证事实来源与算术。原任务是静态问答，缺实时工具反馈。
- **工作动作。** 要求输出必要的决策依据、单位和中间计算，并单独列最终动作。复核时直接检查中间值与原始日志。对确定性统计，用既有脚本复算。
- **验证。** 用已知同卡计时与失败日志，比较直接回答、要求证据步骤、以及用工具复算三组。若错误主要在查不到版本或分母，仅调整提示难以修复。

### `arxiv:2501.12948`

- 原文：[DeepSeek-R1 v2](https://arxiv.org/html/2501.12948v2)
- 范围：§§2.1–2.3、3、4.1–4.2、附录 B.5 和 E、G 的相关段落。核对 R1-Zero 的结果、训练阶段和评估限制。
- **方法。** 用可验证结果和格式奖励训练 R1-Zero。R1 增加冷启动与分阶段训练。作者报告使用更长推理、外部答案正确性信号、以及蒸馏的不同作用。
- **证据与边界。** R1-Zero 训练中 AIME 2024 的平均 pass@1 从 15.6% 到 77.9%，共识解码另报告 86.7%。这些口径需分开看。附录 B.5 显示偏好模型奖励上升而 CodeForces 表现下降。论文将软件工程较长评估时间列为限制。可判数学题的奖励不等同于真实 AI Infra 的正确性与资源约束。
- **工作动作。** 先用输出数值、目标硬件、相同工作量和版本一致等客观信号构成验证。多候选时用实测或保留未知。提高 reasoning 预算前，先核对能否观察到新的决定性数据。
- **验证。** 固定基础工具和输入，分别增加推理预算、补一项有判别力的观测，或增加独立候选。记录可复现的决策成功和每项成本。若模型得分增长伴随缺少正确性或条件篡改，先修验收器。

## 跨来源判断

L5 中增加交互、增加规划层和增加分工都可能改变观察与行动。比较时给简单基线相同的工具访问与成本信息。把日志读取得到的证据、工作流确定性检查、以及真正需要选下一步的环节分别计量。需要外部权限、可比的 GPU 测量或数值正确性时，以真实状态和产物作为验收依据。
