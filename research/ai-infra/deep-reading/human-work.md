# 真实工作、人机协作和评估

### `arxiv:2603.01203`

- 原文：[How Well Does Agent Development Reflect Real-World Work?，arXiv v2](https://arxiv.org/html/2603.01203v2)
- 范围：§2 工作领域及技能映射、§3 覆盖和代表性、§4 工作流复杂度及自治边界、§5.2、附录 B.1。
- 方法：从 O*NET 建立领域与技能树，把基准示例映射到树上，并与就业和技能重要性加权数据比较。从执行轨迹归纳不同粒度的子任务，再以超过预设成功门槛的最高复杂度表示自治水平。
- 证据及边界：19,179 个分析示例中，管理、法律、建筑与工程分别仅占 1.4%、0.3%、0.7%。跨三个以上领域的示例为 8.5%。领域广度、技能数量、轨迹划分是代表性和复杂度的代理指标。论文用模型映射并抽样复核，无法直接从占比估算某个团队的收益。
- 工作迁移：从用户实际工作日志抽样建立评估集。覆盖定位热点、推导可测假设、设计公平对照、改代码、处理环境失败和讨论合入条件。记录各动作出现频率、人工时间及判断风险，按同样粒度检查候选任务集漏了什么。
- 最小验证：对同一系统分别给微基准和含环境、沟通及复核的完整案例，测正确率、人工接手和到可采纳结果的时间。若排名反转或熟悉仓库的成功无法迁移，保留按任务类型和工作条件分层的结论。

### `arxiv:2510.04374`

- 原文：[GDPval，arXiv v1](https://arxiv.org/html/2510.04374v1)
- 范围：§2 职业和任务构造、质检与盲评，§3.1–3.4 对照、成本和脚手架实验，§5 和附录 A.2.1、A.6。
- 方法：按美国 GDP 行业与职业选专家，收集任务说明、参考文件、交付物并迭代审查。总集 1,320 项，公开 gold 220 项。盲评时领域专家读任务与资料，并排序去标识的模型和人类交付物。另训练实验性评委。
- 证据及边界：Claude Opus 4.1 的公开子集产物 47.6% 与专家持平或更好。自动评委与专家一致率 66%，专家间为 71%。不同模型使用的产品工具有差异。时间和成本比较模拟「尝试、审阅、失败后专家自行完成」，不是对真实团队返工时间的直接测量。
- 工作迁移：给旧优化工单制作去标识的候选交付包，含变更、原始测量、正确性、基线和适用条件。让维护者按同一验收说明盲评已有人工结果与新结果，记录偏好理由和合入前还需的工作。
- 最小验证：分别测手工、一次辅助和多次候选选择。记录编写、运行等待、人工审核和返工。用等质量门槛计算到可接受交付的总时间。如果只减少初稿时间，依据剩余人工工作调整委托点。

### `arxiv:2606.09833`

- 原文：[CollabSkill，arXiv v2](https://arxiv.org/html/2606.09833v2)
- 范围：§3 数据和评分、§4 贝叶斯技能估计、§6 表 2–5 与人机结果、附录 B 和 I。
- 方法：从三个职业基准抽取任务，把参与者与 Agent 随机配对。收集交付物及交互记录。用贝叶斯模型区分人和 Agent 的潜在技能，并对评分不确定性降权。另以自动评分和公开人工 rubric 抽样核对。
- 证据及边界：93 名参与者完成 386 场、165 个不同任务。协作排序与自治排序不同。按估计的人类协作技能分层，最高和最低四分位相对同 Agent 自主执行的胜率分别为 74% 和 27%。分层结果反映这一样本及评分方式，不能归因为单个协作习惯，也没有证明对其他用户同样有效。
- 工作迁移：按 GPU profiling 经验、对仓库的熟悉度和任务类型配平。比较同一模型的纯执行、允许重定向和允许修改产物。分别记录人工修正的作用、交接次数、用户投入和终稿质量。
- 最小验证：让同一人做不同但配对的工单，随机交换工具方案顺序，用相同的隐藏正确性和性能检查。留出少量任务做人工审计。按用户和案例报告配对差值，避免少数高手或异常长任务支配平均值。

- 范围：§2 审计、参与度量表及双视角，§3 意愿和技术能力地图，§4 讨论，附录 A、B、D。

- 范围：问卷、访谈、Claude Code 使用轨迹、向前展望、附录方法与限制。
- 方法：132 名员工问卷、53 次深入访谈，与 2025 年 2 月及 8 月内部 Claude Code 的 20 万条轨迹结合。用调查记录认知及取舍，用日志比较任务类别、推定复杂度和工具使用行为。
- 证据及边界：受访者报告平均生产率提升约 50%。日志估计的任务复杂度从 3.2 到 3.8，最长连续工具调用均值从 9.8 到 21.2。调查为单家公司、非匿名且包含回忆偏差。日志比例抽样只能比较相对分布。连续调用数不能衡量任务质量或省下的人工时间。

- 最小验证：连续记录若干匹配任务的开始、有效输出、人工审阅、返工和后续采用。把主观节省时间与日志对照。若代码变更量增加而可采纳的性能改动没有增多，检查验证工作是否成为新瓶颈。

### `arxiv:2604.06996`

- 原文：[Self-Preference Bias in Rubric-Based Evaluation，arXiv v3](https://arxiv.org/html/2604.06996v3)
- 范围：§2 错误放行率及评委设置，§3–4 客观和主观 rubric，表 1–2，附录 L 的比率分母和绝对值。
- 方法：先把 IFEval 程序化要求和 LiveCodeBench 隐藏测试转成二元 rubric，再比较评委在客观失败条件下对自己和其他模型输出的错误放行率。对主观任务使用跨模型委员会做参照，并分别检查模型家族及评委提示。
- 证据及边界：GPT-5 在 LiveCodeBench 的平均 rubric 准确率为 0.97，同条件下自身错误放行比率为 20.15。该比率以其他生成者错误放行率为分母，不能解释为高 20 个百分点。偏差依赖任务和模型。没有客观真值时委员会本身也可能有系统误差。
- 工作迁移：用确定性检查裁定 dtype、shape、误差和计时匹配。模型可评价推导可读性和解释是否指向真实证据，使用留出人审校准。将生成者隐藏后仍要对同模型与跨模型评委分别统计误拒和放行。
- 最小验证：同一组优化方案包含有已知隐蔽错误的变体。比较原模型自评、异模型评审和确定性检查加人审。报告各类错误绝对分母、放行率、评审一致性和时间，检验高平均分是否掩盖关键回归。
