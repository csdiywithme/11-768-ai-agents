# L06 深读 · 跨语言验收、结构化定位和可视证据

本批细读七项登记来源。比较基准构造、观察渠道、目标定位与重试语义。下列 AI Infra 应用为待验证的假设。

### `arxiv:2504.02605`

- 原文：[Multi-SWE-bench: A Multilingual Benchmark for Issue Resolving](https://arxiv.org/html/2504.02605v1)
- 范围：arXiv v1。细读 §§3.1–3.2、§§5.1–5.2、§§6.1–6.2 和 §6.4，核对人工筛选、资源表和工具差异。
- 机制：从七种语言的 39 个仓库构造可执行任务，经自动筛选留下 2,456 项，双人标注与交叉复核后留下 1,632 项。验证既要确认新测试能发现原问题，也要查原有行为是否回归。基准适配了三种工具。资源表中 Python 使用未引入相同截断机制的版本，因此跨语言 token 差异受工具实现影响。
- 改变的动作：在 PyTorch 扩展、C++ runtime 和 Triton 上分别验收。按症状、工具、依赖和工程规模分组。把构建失败、复现失败、代码定位、有效修复和性能回退分开记录。用同工具上限或报告不同上限解释各组结果。
- 推翻条件：若一项差异随超时、日志截断、任务难度或测试覆盖变化而消失，撤回将差异归因到编程语言的判断。论文的功能优化分类与 GPU 性能验收仍须独立设计。

### `https://www.swebench.com/multilingual.html`

- 原文：[SWE-bench Multilingual 官方介绍](https://www.swebench.com/multilingual.html)
- 范围：细读 benchmark construction、环境镜像设计、人工验证、结果和语言差异讨论。
- 机制：本项目单独构造 42 个仓库、九种语言的 300 项任务。项目保留基础和实例镜像，省去共享环境镜像，原因是任务间依赖重合较少。人工确认旧实现未通过新测试、参考改动能通过，并排除错误信息等实现细节过度约束的测试。Claude 3.7 Sonnet 与 SWE-agent 在每项成本限额 2.50 美元下解决 43%。原文对比 Python Verified 的 63%，同时承认缺少人工难度标注。
- 改变的动作：先测试不同 CUDA 版本、编译器和模型间复用多少构建依赖。共享程度低时，使用固定基础环境与独立实验配置。编写验收时从行为和资源约束出发，允许多种等价优化。
- 推翻条件：若实例镜像维护成本高于节省的启动时间，改用共享模板。若跨栈差异在难度匹配后消失，按真实工作阶段解释分数。该来源与 Multi-SWE-bench 是独立构建的任务集。

### `arxiv:2410.03859`

- 原文：[SWE-bench Multimodal: Do AI Systems Generalize to Visual Software Domains?](https://arxiv.org/html/2410.03859v1)
- 范围：arXiv v1。细读 §§2–4、Appendix B.3、D.2–D.3 与 E，核对 Table 5 的图像必要性和工具移植实例。
- 机制：以主要为 JavaScript 的仓库测试真实视觉问题，保存原图、视频和复现资源以避免原链接失效。作者先让人不看图判断可解性，再看图。被判定需要图像的子集里，SWE-agent JS 与 Claude 3.5 Sonnet 的解决率从无图的 8.8% 到有图的 17.6%。判定不需要图像的子集出现反向结果。作者也记录了 Python 专用定位逻辑移植时的额外工作。
- 改变的动作：给 Nsight Systems 时间线分别保留机器可读 trace 和带单位、窗口及设备的截图。只有时序重叠、空间位置或结构关系无法由摘要稳定表达时，引入图像来决定下一步。把图像与源数据按 run ID 和时间轴关联。
- 推翻条件：固定模型和任务比较结构化数据、截图、两者联合。若截图增加错读时间轴或单位的次数，先让程序导出关键区间和数值。不能把视觉任务分数差换算成 GPU 瓶颈定位收益。

### `arxiv:2401.13649`

- 原文：[VisualWebArena: Evaluating Multimodal Agents on Realistic Visually Grounded Web Tasks](https://arxiv.org/html/2401.13649v2)
- 范围：arXiv v2。细读 §§3.1–3.3、§§5.1–5.3、§§6–6.1，以及 Appendix C 中 OCR 和失败模式相关段落。
- 机制：比较 accessibility tree、描述补充、截图和标注交互对象的 Set-of-Marks。GPT-4V 从截图加结构树的 15.05% 到用 SoM 的 16.37%，其他受测 VLM 不一定改善。评分用 URL、页面元素、视觉相似或视觉问答等条件表达最终状态。
- 改变的动作：在 profiler 截图上为每条 stream、kernel 和时间区间生成与 trace 对齐的 ID。模型选择下一项观测时引用 ID，独立程序检查 ID 所属运行及区间。优先用可计算的统计量核验读图推断。
- 推翻条件：若标注导致 OCR 错误、拥挤或失去关键比例，比较局部截图或结构化导出。若截图仅改善解释、未改善定位或下一项测量，保留原观察接口。图像相似度只适用于相应的可见属性。

### `https://playwright.dev/docs/locators`

- 原文：[Playwright Locators](https://playwright.dev/docs/locators)
- 范围：截至 2026-11-13，细读 locator 解析、role、test id、过滤和严格匹配部分。
- 机制：执行动作时按当前 DOM 重新查找匹配项。要求单目标的动作遇到多匹配时抛出异常。统计匹配项的动作可以返回多个。文档建议使用用户可见的角色与名称，或明确的 test ID 契约。
- 改变的动作：对仪表盘、实验管理界面和产物选择使用稳定语义标识。使用 run ID、设备和指标组合做精确选择。存在多个匹配项时返回候选及区分字段，让后续动作重新选择。
- 推翻条件：用相同输入改变 DOM 顺序、改页面布局或加入同名元素，比较误选率和人工维护。若没有稳定契约，优先比较 API 或导出的产物入口。UI 定位通过不能证明原始数据对应同一次运行。

### `https://playwright.dev/docs/test-assertions`

- 原文：[Playwright Assertions](https://playwright.dev/docs/test-assertions)
- 范围：截至 2026-11-13，细读自动重试、普通断言、`expect.poll`、`expect.toPass`、软断言与自定义 matcher。
- 机制：异步断言会重新检查直至满足或超时。普通断言读取瞬时状态，复杂条件可设置轮询间隔和期限。软断言可继续收集失败信息，测试仍保留失败记录。
- 改变的动作：异步 benchmark 完成后，轮询只读状态和对应 run ID。等待产物出现与验证内容各有条件。轮询到截止仍未完成时，保留最后一次状态与已通过步骤。对性能值按预定采样和统计口径验收。
- 推翻条件：在产物延迟、失败或已有上一轮结果的条件下检查误通过。若自动轮询反复读取同一个旧文件，增加运行标识和更新时间约束。若重试的是有副作用的启动动作，改为查询同一个已知运行。

### `https://playwright.dev/docs/test-snapshots`

- 原文：[Playwright Visual comparisons](https://playwright.dev/docs/test-snapshots)
- 范围：截至 2026-11-13，细读参考快照生成、环境影响、更新与容差选项。
- 机制：无参考图时会等待相邻两张截图稳定，再保存参考。不同浏览器、平台、字体、配置和硬件可造成正常变化。文档提供可控的比较和快照更新入口。
- 改变的动作：如果诊断工具用静态图检验 dashboard，固定浏览器和渲染配置，存参考图与生成版本。更新参考图前先核对原始指标和范围。对 trace 或 benchmark 则以可比较的原始事件与数值为依据。
- 推翻条件：若图像差异主要来自环境、渲染或轴缩放变化，采用结构化断言或缩小比较范围。若固定环境仍会漏报实际性能回归，继续使用机器可读的性能验收。
