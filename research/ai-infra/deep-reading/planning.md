2026-11-13 阅读批次。以课表 L5 登记标识定位原文。版本号来自论文页，正文范围逐项标记。实验数字均是论文报告。工作动作和对照设计是从原文推导的应用假设。

### `arxiv:2503.09572`

- 原文：[Plan-and-Act v3](https://arxiv.org/html/2503.09572v3)
- 范围：§§3.1–3.4、4.1–4.3、5.1–5.3 的实现、数据及消融，核对 Table 1–2。另看 §5.4–5.5 的两种测试环境和作者仓库运行入口。
- **方法。** Planner 输出高层步骤，Executor 依据当前 HTML 生成动作。动态方案每个执行步骤后将当前状态、之前的计划与动作交回 Planner。原计划会被重写，已发现的信息也可写入新计划。训练时先用环境得到的成功轨迹逆向标注计划，要求计划步骤对齐实际动作，再用已有计划扩增，并用失败分析定向补例。
- **证据与边界。** 在 WebArena-Lite 的 165 个测试题上，Table 1 同一 Executor 列中无 Planner、未训练的 Planner、定向扩增后的静态 Planner 和动态重规划分别为 36.97%、23.63%、43.63%、53.94%。57.58% 还包含新的推理数据。动态行同时增加了重规划训练数据和运行中的反馈，不能将 10.31 个百分点单独归因于运行中多一次模型调用。论文 §5.3.2 的文字差值与表中 53.94→57.58 的差不一致，此处用原表。环境反馈丰富并有任务判定。实验未隔离实际调用成本、人工接管和 GPU 调度代价。
- **工作动作。** 针对 B300 或 DeepInfer，把工程目标、候选机制、前置状态和改选条件放进计划。读到新的可靠结果后，保留目标、有效证据和已经完成的测量。只重排受影响的后续步骤。把计划写成可定位证据的决策记录，执行层只负责取得明确的日志、配对计时或 trace 数据。
- **验证。** 给人工、固定流程、逐步骤重规划和仅在观察改变机制判断时重规划同一组决策前缀。以相同模型和工具预算比较选错下一项、遗漏硬件或正确性约束、人工主动时间和预期 GPU 成本。如果简洁规则已捕捉同样的分叉，就保留触发规则。只有稳定的剩余错误才值得将历史计划前缀做成示范。扩展核对发现仓库单列静态与动态入口，README 的运行依赖 WebArena-Lite，不能据此证明 Infra 可直接复用。 [作者仓库](https://github.com/SqueezeAILab/plan-and-act#usage)

### `arxiv:2311.05772`

- 原文：[ADaPT v2](https://arxiv.org/html/2311.05772v2)
- 范围：§§3.1–3.3、4.2、5、6.1–6.5 及 Limitations。核对 Table 3 的深度分层和 Figure 7 的调用预算文字。
- **方法。** 先由 Executor 直接尝试。不能继续时才请 Planner 划成少量子任务，递归求解。AND 表示一组有序条件都要通过，OR 表示探索分支只需一个成功。控制器负责深度上限。方法用 Executor 根据历史动作与环境文字自报完成，作为中间成功判定。
- **证据与边界。** 共用 GPT-3.5 执行器的 ALFWorld 对照中，作者报告比 ReAct、Plan-and-Execute 各高 28.3 个百分点，比全任务重试高 23.8 个百分点。TextCraft 中配方深度 2、3 的成功解分别用到平均 1.9、2.8 层分解。Table 3 排除了仅 11 项的深度 4 分层。§6.5 的平均模型调用数与重试类基线相近，调用数不衡量 token、工具副作用或墙钟。中间成功自评依赖环境反馈清晰，不能直接当作数值正确或任务终态。
- **工作动作。** 日常可从一个可逆的已有记录读取开始。若它不能区分无效采集、解析器错配或真实瓶颈，再将诊断拆成子问题。DeepInfer 观察器超时后先查原调用的服务端状态。只在状态无法核清时展开后续分支。已通过的预检和已经完成的任务无需从头重做。对每个子任务绑定机器可检验的输出，或明确证据不足。
- **验证。** 对同一批有重试记录的诊断，比较顺序预检、失败后局部分解、全任务重试。注入采集器空输出、成功退出但目标断言未运行、观察器超时但服务器运行三类记录，测误判完成、重复动作和恢复用时。若分解无法提高关键失败的判定正确性，优先修成功信号。作者项目页展示三种环境中的分解和复杂度结果，未将演示当作额外独立验证。 [作者项目](https://allenai.github.io/adaptllm/)

### `arxiv:2210.02406`

- 原文：[Decomposed Prompting v2](https://arxiv.org/html/2210.02406v2)
- 范围：§§3.1–3.3、4.1–4.5、5。核对 Figure 3 的控制器、Figure 9–10 的粒度对照和 Figure 12 的检索对照。
- **方法。** 分解器根据已完成的问答选择下一个子问题和处理器。控制器传递结果、展开 `foreach`、按结束标记收束。处理器可以是独立提示、另一个分解程序、计算器或检索器。同一个子模块的示例可以脱离上层任务独立更新。
- **证据与边界。** 合成 CommaQA 上两种粒度都比其 CoT 对照好，细粒度的增量较小，需要维护更多专用示例。开放多跳 QA 在每个数据集的 300 个 dev 问题上测试。分解检索多数情况下胜过直接检索，Codex 的 HotpotQA 是相当的反例。测试的是问答准确率和 F1。它没有测日志字段歧义、远程调用成本或最终交付错误。
- **工作动作。** 把找证据和读证据分别显式处理。给 trace、计时结果、编译状态三个可复用处理器。回传结构化读数以及 run ID、源码版本、分母和原始位置。允许规划器在观测改变后选择另一个处理器。只有数据依赖明确的分组才做批处理，例如用同一协议核对多个独立形状。
- **验证。** 给两组同样的源文件和查询预算。一组直接调查，一组能复用三个处理器。分别测定位正确记录、提取关键字段、保留跨文件关联和选对下一步。若模块拆开只增加调用，或丢掉需要联合解释的同请求状态，就合并相关处理步骤。

### `arxiv:2204.01691`

- 原文：[Do As I Can, Not As I Say，SayCan v2](https://arxiv.org/html/2204.01691v2)
- 范围：§§3–5、8。核对 Figure 5 的计算与停止条件、Table 2 的能力消融及不同厨房的评估。
- **方法。** 对每项预定义技能，语言模型根据指令和已选动作打任务相关分，价值模型根据当前环境状态估计可执行成功概率。两项相乘后选技能，执行并刷新状态，再重复选择。技能定义、低层执行和能力估计可独立检查。
- **证据与边界。** 101 项任务的模拟厨房实物布置中，PaLM-SayCan 的计划和执行成功率分别为 84%、74%。移除价值函数后计划成功率为 67%。长任务出现提前停止，技能价值也会误判。论文的技能库和机器人环境与 GPU 工作不同。在线工具可用、能排队或返回成功状态，都只能证明某一层能力。
- **工作动作。** 优化候选排序前，先读取当前设备、编译目标、工作负载、数据和权限。用确知的硬条件排除无法执行的动作，再比较其是否能区分假设。比如环境尚未验证目标架构时，可以先核对生成的实际 PTX target。已有足够计时反例时，可以先复算漂移，再决定是否申请 A/A。
- **验证。** 用同一决策前缀修改预编译镜像、trace 可用性和 GPU 成本。比较单独按相关性、确定性前置条件加相关性、以及额外使用历史成功率三种排序。测不可行动作、错过有判别力的候选和提前停止。只有成功率按目标环境校准后才考虑将其纳入排序。

### `arxiv:2206.10498`

- 原文：[PlanBench v4](https://arxiv.org/html/2206.10498v4)
- 范围：§§3–7 及附录 A.2–A.4。核对 Table 1 的任务分项、Table 2 的改名对照和放宽约束的错误分析。
- **方法。** 用 PDDL、问题生成器及独立计划验证器评估计划生成、费用最优、验证、预测执行后状态、重规划和复用。翻译层把自然语言映射回形式表示。可以换对象、动作和谓词名称而保留同一状态转移。
- **证据与边界。** 文中 8k 上下文的 GPT-4 在 Blocksworld 的生成、验证、重规划分别为 206/600、352/600、289/600。生成题换成随机名称的 Mystery Blocksworld 后为 12/600。只能说明该设置和模型对命名敏感。作者附录发现连忽略前置条件和删除效果的宽松验证也仍有不少失败。仓库后来增加其它模型、输入格式和硬题，README 的零样本表与旧文的少样本表不能直接合并。 [作者仓库与现行静态榜单](https://github.com/karthikv792/LLMs-Planning#planbench-static-test-set-leaderboard)
- **工作动作。** 从云调用恢复和 scheduler 回放选已知状态转移。冻结动作前置和目标状态。允许多个有效计划。分别构造可执行但无助于目标、会重复提交、成本高但有效、已有结果足够可停止四类。用独立 verifier 检查状态，而非把有格式的计划文本当成完成。
- **验证。** 给同一场景更换文件名、日志标签和系统术语，同时保留事件先后及约束。另做一组名称相似而终态不同。若成功率随表面标签显著变化，就优先修观测抽取和状态契约。带随机成本的样本要分别报告有效性和成本，避免用单一分数掩盖错误运行。

### `arxiv:2201.07207`

- 原文：[Language Models as Zero-Shot Planners v2](https://arxiv.org/html/2201.07207v2)
- 范围：§§2.1–2.2、3.1–3.4、4.1–4.3、5.1、7。核对 Table 1 的执行率、人工正确性与限制。
- **方法。** 在 VirtualHome 枚举中间层动作，用嵌入相似度和生成概率把自然语言建议映射到环境接受的动作。交替生成和映射，每次将已映射动作加入上下文。动作分数过低时可停止。
- **证据与边界。** Table 1 的 Codex 12B 经过映射后，执行率由 18.07% 升至 78.57%，人工判断的任务正确性由 64.87% 降至 54.88%。方法没有直接用当前环境观测或反馈，动作空间也有限。有合法接口的动作仍可能误改目标。
- **工作动作。** 将自然语言实验意图解析成有限的已知动作，例如读取现有 trace、做编译检查、提出 A/A、选样或停止。映射时保留候选原意及已核实参数。对不匹配的 GPU、精度、版本或计时分母保持未知。不能因为一个工具可以调用就静默换用另一类数据。
- **验证。** 用含歧义的任务，比如仅要求定位性能问题却附有多份不同 GPU 的结果。分别检验语法可执行、状态合法和是否回答实际问题。把最接近的可执行动作与明确拒绝映射作为对照。若映射使执行率升高但任务正确性下降，优先修正契约和缺参处理。

### `arxiv:2205.10625`

- 原文：[Least-to-Most Prompting v3](https://arxiv.org/html/2205.10625v3)
- 范围：§§2、3.1–3.3、5。核对 Table 4 及 Table 11–12 的长度和步骤分层。
- **方法。** 先分解，再从可先回答的子问题逐个求解。把前面答案带给后续，最后解原问题。子问题通常互相依赖。每个新领域需合适的分解示例。
- **证据与边界。** 同一 code-davinci-002 设置下，12 项末字拼接的准确率为 74.0%，CoT 对照为 31.8%。GSM8K 的至少 5 步分层由 39.07% 升至 45.23%，2 步分层则由 76.68% 降至 74.53%。任务、模型和提示决定效果。长链中未验证的早期答案会进入后续。
- **工作动作。** 将框架回归问题拆成前置证据。先定位首个状态变化，再核对受影响请求是否有剩余配额或被访问，最后判断哪条修改能改变转移。中间结论应绑定轮次、状态字段和版本。
- **验证。** 对短而确定的预检和长而依赖前序状态的任务分别比较一轮直接判断与逐步流程。保持总预算可比。向一条前序记录加入缺失 rank 或重复计数，检查后续是否发现并停止传播。若短任务的效果退化，让直接流程先处理。

### `arxiv:2209.11302`

- 原文：[ProgPrompt v1](https://arxiv.org/html/2209.11302v1)
- 范围：§§III.A–III.C、IV、V.A–V.C。核对 Table I 的反馈消融及 V.B 的执行和目标误判。
- **方法。** 提示中给出可用动作、对象和完整任务示例。模型用类似 Python 的结构表示方案。环境解释器执行受控动作。虚拟实验在断言失败时可以走恢复分支，物理桌面实验没有采用同样的断言闭环。
- **证据与边界。** Table I 同一 GPT3 设置下，有注释与反馈的完全成功率均值为 0.34。保留注释去掉反馈为 0.28，执行率分别为 0.84、0.82。V.B 指出，有合法动作也可能遗漏打开柜门等隐含前提。单一目标状态还会误罚其它可接受解。机器人实验只能支撑表示与验证启发，不能推断 Infra 结果。
- **工作动作。** 对重复实验提供显式前置条件和可恢复分支。提交前核对镜像、队列目标、输入版本和已运行任务 ID。过程状态来自真实工具回执。工具调用失败时读取同一任务状态，再决定继续观察、返回证据不足或修输入。验收使用正确性、形状和计时口径等谓词，允许不同产物命名。
- **验证。** 用相同历史记录分别给文字计划、结构化动作和带断言恢复的流程。测是否命中第一失败阶段、是否重复请求以及最终是否形成可审查结果。测试目标应允许多个有效到达路径。若环境状态缺字段，优先补观测。

## 跨来源判断

计划文本、执行可行性和工程目标达成需要各自的观测。第一项回放应让简单流程也具备当前状态、预算和可执行的预检。将正常分支、关键反证和证据不足分开。用 Plan-and-Act 比较何时重规划，用 ADaPT 比较何时细分，用 SayCan 和 PlanBench 检查可执行与有用是否同时成立。只有仍会漏掉改变下一步的证据时，才测动态调查的增量。

本批扩展从 Plan-and-Act 作者仓库跟到静态与动态运行入口，从 ADaPT 跟到作者演示，从 PlanBench 跟到静态榜单及代码目录。只核对公开入口和其说明，未执行外部实验。
