### `https://www.openhands.dev/blog/20260227-creating-effective-agent-skills`

- 原文：[OpenHands How to Create Effective Agent Skills](https://www.openhands.dev/blog/20260227-creating-effective-agent-skills)
- 范围：L4 pp.8–9、14–15。读 2026-02-27 正文的技能触发、编写、部署及线上监控章节。相关 PR 评估 workflow 的链接返回 404。
- 方法与证据：为重复且步骤稳定的工作编写技能包。先显示发现信息，按需读正文和脚本。作者的代码审阅案例记录工具轨迹，通过人工回应和最终 diff 是否体现建议估计采纳，再据失败模式修订技能。文章给出了流程和仪表盘示例，缺少匹配的对照结果。采纳是代理指标，也受仓库习惯和作者优先级影响。
- 工程动作与反证：从已经复核的一次 benchmark 核验或 trace 解析写短技能，保留触发条件、失败处理和原始产物。记录是否命中、是否完成和是否需要人工返工。用独立工程任务比较手工清单与技能，分别报告准确度与采纳。若命中率高但错误复测增加，检查技能适用条件和验证步骤。
- 同站扩展：官方当前 Creating New Skills 文档的 Defining Triggers 列出关键字与路径规则。测试时可分开检查自动注入、模型选择和正文是否实际生效。该规则属于 OpenHands。 [Creating New Skills](https://docs.openhands.dev/overview/skills/creating)

### `arxiv:2602.12670`

- 原文：[SkillsBench v4](https://arxiv.org/html/2602.12670v4)
- 范围：L4 pp.12–13。读 §§3–6、附录 D.6 与 F 的失败分类选段，核对 Tables 2–3、6，使用 v4 的试次与分母。
- 方法与证据：87 个容器任务按任务配对，对照有无人工整理技能包，用确定性测试评分。18 个模型与 harness 组合均有聚合提升，宏平均为 33.9% 到 50.5%，各组合增量差异较大。另有三个组合的同题自动写技能再解题条件，均低于无技能 8.1–11.5 个百分点。后者包含生成、发现与使用问题，其中 Claude Code 的 effort 与基线不同。
- 工程动作与反证：在预设设备和固定来源状态下比较无技能、手工核查的技能、自动提取技能。将技能读取、行动和任务验收分开计分。用难度和硬件切片检查哪类任务退化。另设长度接近的普通参考文档，用于检验效果是否来自技能结构。若提示变长而决策与工时未改善，优先给确定性检查和必要片段。
- 边界：作者指出任务为可重跑的终端容器工作。资源长时间排队和线上服务状态需要另测。确定性验收可用于正确性与输入契约，工程诊断还可用人工评审接受多种有效动作。

### `arxiv:2106.11053`

- 原文：[LAPS v1](https://arxiv.org/html/2106.11053v1)
- 范围：L4 p.23。读 §§3–4 的先验、§§5.1–5.3 的联合模型与压缩、§§6.1–6.2 的 Table 1 及 §7。
- 方法与证据：同时学习程序及其语言说明。语言线索用于引导搜索，也用于形成能和语言概念对应的程序抽象。对 111 个留出图形任务，DreamCoder 的合成训练与测试平均为 42.64%，带语言搜索、mutual exclusivity 和联合压缩的 LAPS 为 81.98%。真实文本的实验只报告该表的部分口径，且有较低的 best 值。其他域的不同消融也不齐增。
- 工程动作与反证：把优化假设和工具接口用已复核的工程概念描述，例如「确认统计区间是否包含图重放」和「按同请求关联事件」。比较用真实语义标签、只给签名、以及打乱标签三种条件。若标签未提高陌生运行的证据检索或动作选择，先检查接口是否已足够明确。

### `https://aclanthology.org/2026.acl-long.69/`

- 原文：[SAGE ACL 2026 正式论文](https://aclanthology.org/2026.acl-long.69.pdf)
- 范围：L4 p.43。读 ACL pp.1530–1538 的任务链、技能奖励、Tables 1–4 与 Limitations，核查 SFT 初始化。
- 方法与证据：任务链内，首任务发现的代码技能在后续相关任务可调用。强化训练的奖励加入后续任务实际使用先前技能并成功的信号。AppWorld 的 Qwen2.5 32B test challenge 整任务完成率，技能库提示 15.3%、加 SFT 37.2%、再做 SAGE 50.1%，基线 GRPO 40.7%。SFT 使用 Claude 经验。未训练技能库还低于同底模 ReAct 的 21.0%。作者只在 AppWorld 验证。
- 工程动作与反证：若已有工具稳定，测模型能否在相邻但不同的实验中复用已验证的操作。任务对按同机制和不同接口分组，记录调用成功与最终工程决策。先对照固定流程、示范和模型自然使用技能，只有可稳定标注的失误仍出现才考虑训练。若训练只提高工具调用次数，或只在同框架有效，不支持扩大训练投入。

### `https://aclanthology.org/2026.acl-long.981/`

- 原文：[AgeMem ACL 2026 正式论文](https://aclanthology.org/2026.acl-long.981.pdf)
- 范围：L4 p.43。读 §§3.1–3.5、4.1–4.2 及 Limitations，核对 Tables 1–2 和训练任务来源。
- 方法与证据：把添加、更新、删除、检索、总结、过滤作为模型可选工具。先收集早期信息，再处理干扰，最后完成需要两类记忆的任务。用 HotpotQA 构造三阶段训练轨迹，奖励含任务成绩、上下文和长期记忆管理。Qwen2.5-7B 的五基准平均，No-Memory 28.05%、同工具无 RL 33.43%、AgeMem 41.96%。单项并不齐增，如 PDDL 中该模型结果 17.31%，A-Mem 为 18.39%。真实用户长期任务仍缺验证。
- 工程动作与反证：先让任务状态提供保存、检索和压缩操作。原始实验产物保留独立入口，历史条件可查询。用有干扰日志的回放测该保留与该取回的项，以及做错后的决策变化。若简单的状态字段和确定性检索达到同效果，保持简单流程。需要学习的应是可明确复核的时机选择。
