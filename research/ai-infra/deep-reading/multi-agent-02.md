- 范围：与课程快照 SHA-256 一致的官方缓存。读完 44 页文字，另核查 p.2、10、15–16、18–20、22–23、25、28、32、34、36、43 的图。线上入口本次未返回文件。
- 方法：课程用联合动作与局部观察描述多 Agent。p.3–25 比较角色分工、按需委托、隔离工作区、共享任务板、Git 协作和有验证信号的探索。p.26–37 展开人机交互、模拟器、语言约定和市场。p.38–43 讲信息校准与辩论监督。
- 证据及边界：p.19 的等待图是 DeLM 单个案例。p.24 给出同样两个尝试时，Terminal-Bench 2.0 的独立 pass@2 为 62.36%，团队为 60.67%。p.25 强调只有中间进展可核验，且可用预算能支付沟通时，团队可能复用对方发现。图示和经验结果需按对应论文配置解读。
- 工作迁移：把可并行探索的算子路线、存在集成依赖的框架改动、依赖用户决策的 workload 诊断分别安排。用明确的观察、状态、候选 commit 与共同评分把它们接起来。调度只在能减少重复或解除依赖时加入共享通信。
- 最小验证：同预算比较单路深入、独立候选加选择、共享已验证发现、协调分支四组。选一个可拆与一个高度串行任务，记录总成本、等待、重复测量、因同行发现改判的次数与最终回归。

### `https://www.marl-book.com/`

- 原文：[Multi-Agent Reinforcement Learning: Foundations and Modern Approaches，MIT Press 2024 书稿](https://www.marl-book.com/download/marl-book.pdf)
- 范围：官网目录与原书 §1.1–1.4、§3.3–3.5、§5.3–5.4、§9.1。围绕课程所用联合动作图及运行所需局部观察选读。
- 方法：随机博弈以联合动作驱动状态转移。部分可观察情形下，各方只读自己的观察历史。书中区分独立训练与执行、集中训练与执行、集中训练分散执行。后者可用联合观察训练 critic，执行策略仍只读局部信息。
- 证据及边界：§5.4 用采集任务解释共同奖励为何难归因，多个学习者会使单个学习者看到的环境非平稳。联合动作组合可能随独立动作维数乘法增长。教材中的机制依赖游戏模型及信息假设。实际工作是否需要训练策略取决于重复性、数据及反馈。
- 工作迁移：把调度器、算子试验执行器和验证器的可见状态、动作、成本及共同目标写清。训练或分析可读取合并日志，运行时按许可只提供必要观察。候选之间共用一块 GPU 时，记录联合运行是否改变单次测量。
- 最小验证：对同一任务回放日志，比较单进程调度、按局部信息独立执行、共享关键状态。用同形状和同预算查看归因错误及重复操作。将单个候选移除后重放，可检查最终结果依赖谁的贡献。

### `arxiv:2305.14930`

- 原文：[In-Context Impersonation Reveals Large Language Models’ Strengths and Biases，arXiv v2](https://arxiv.org/html/2305.14930v2)
- 范围：§3 角色提示和实验任务，§4.1–4.3、图 4，§5–6 的偏差与范围。
- 方法：用多个提示模板改变模型扮演的角色，测双臂选择、MMLU 和描述辅助的视觉分类。推理实验比较任务专家、同领域其他专家、领域外专家和中性角色。
- 证据及边界：Vicuna-13B 在 MMLU 的四个领域平均都表现为任务专家提示较强，某些具体任务例外，例如高中宏观经济学的任务专家接近随机。其他实验也出现与角色相关的偏差。该结果来自有限模型、角色和单 Agent 任务。
- 工作迁移：将「验证数值边界」「检查测量是否配平」「提出替代瓶颈」定义成各自要完成的动作和可用工具。角色称呼只是一种可测试的提示成分。领域知识要通过来源、脚本和结果验证。
- 最小验证：对真实历史案例固定模型、材料和预算，比较中性任务描述、专家称呼、明确工具与验收三个提示。评价正确发现及额外引入的错误。若只有语言看起来专业，保留可核查的职责描述。

### `https://docs.langchain.com/oss/python/langchain/multi-agent/subagents-personal-assistant`

- 原文：[LangChain 官方，Build a personal assistant with subagents](https://docs.langchain.com/oss/python/langchain/multi-agent/subagents-personal-assistant)
- 范围：§1–5 工具、专用 Agent 包装和主管，§6 人工审核及中断恢复，§7 上下文与返回信息控制。公开文档页。
- 方法：主管把子 Agent 当作工具调用。子 Agent 拥有独立提示、上下文和一组工具。应用状态可经 runtime 传入必要约束，工具返回值可带结构化信息。敏感动作中断，由可修改、接受或拒绝的决定继续。
- 证据及边界：教程用日历和邮件演示跨领域工具分配及恢复，未给准确率和成本对照。默认子 Agent 只拿主管转述的请求。中断 ID 按运行生成，恢复依赖对应状态和决定。
- 工作迁移：为 profiler 解析、benchmark 启动和结果审查配置最小工具集合。传入 commit、GPU、shape、基线和预算。需要运行有成本作业时保留可修改的执行提议、任务 ID 和确认后的参数。
- 最小验证：让同一模型完成一个单域任务和一个跨域任务，比较直连工具和主管加专用子 Agent。注入一次停顿和一次工作负载更正，检查是否重复执行、是否丢失条件，并计量总耗时。

### `arxiv:2510.01285`

- 原文：[LLM-based Multi-Agent Blackboard System for Information Discovery in Data Science，arXiv v2](https://arxiv.org/html/2510.01285v2)
- 范围：§2–3 数据发现、文件簇及公告板，§4 表 1、图 2 和对照，附录 F 的聚类与配置分析。
- 方法：离线按文件名和内容建立组。主 Agent 提交它需要的信息，文件及搜索 Agent 判断是否响应，结果写到响应板供主 Agent 编程和汇总。比较一次 RAG、由主 Agent 点名的助手及公告板。
- 证据及边界：表 1 的 Gemini 2.5 Pro 宏平均，公告板 28.53%、点名 24.01%、RAG 18.51%。不同模型和单任务并非都同序。结果依赖候选文件分组、帮助响应成本和主 Agent 是否会提出能定位资料的请求。
- 工作迁移：将代码、trace 导出、硬件规格和实验记录建成可独立询问的来源。主 Agent 提交具体证据需求，如「找同一机器和形状的基线」，各来源返回带链接和条件的结构化结果。明确超时与空回应。
- 最小验证：在相同 token 与模型预算下，比较直接检索、由主 Agent 指定数据源、多个来源自行响应。分别记录召回正确证据、归因正确和响应开销。加入跨来源条件冲突，检查哪种流程能发现不配平。

### `arxiv:2610.04862`

- 原文：[GitSwarm，arXiv v1](https://arxiv.org/html/2610.04862v1)
- 范围：§2 commit 依赖、异步执行及候选读出，§3.3–3.5 研究轨迹和消融，§4 限制，附录 F–G。
- 方法：每个执行者从一个 commit 在独立工作区开始，可发布原子改动、提名已有候选或结束。commit 同时记录代码父节点及从其他分支读取的证据。候选提名与产物分开。GPU 研究用验证性能选择。
- 证据及边界：九个 ProgramBench 开发任务中，50 个 worker、并行度 5 时，异步 38.0 分钟、同步 49.3 分钟，分数分别为 62.06% 和 63.11%。研究实验中的递归模型候选在 128 条验证样本时被拒绝，扩大样本后复核成功。工件读取和自报依赖说明复用，不能单独归因性能变化。GPU 对照资源和训练 token 并非普遍匹配。
- 工作迁移：保留候选、实验配置、旧拒绝理由、后来复查和可重放日志。发布记录区分依赖的代码和依赖的证据。控制同卡并发造成的计时污染。对性能效果使用硬门槛和保留的 workload。
- 最小验证：同一候选以相同剩余预算分叉，一组可读全部旧实验及反证，一组只读代码和任务。比较重复测量、被重新证实的假设及 held-out 性能。再用不同样本量判断早停排名有多不稳定。

### `https://nickatomlin.github.io/blog/user-simulators-2.html`

- 原文：[What does it take to build a human-like user simulator?，Tomlin 与 Lin，2025-09-25](https://nickatomlin.github.io/blog/user-simulators-2.html)
- 范围：全文 Context、Scaffold、Objective 三节及 DialOp 示例。作者讨论文章。
- 方法：先区分可以直接写成条件的背景和难以从对话获取的潜在知识或偏好。用交互时机控制信息披露，例如在看到两个具体方案时才允许表达选择。把用户行为与结果评价所能使用的信息分开。
- 证据及边界：DialOp 示例用含糊偏好和有限的评分查询模拟逐步澄清。作者提出长期用户轨迹、任务相关模拟资料和认知负荷建模的方向。文章没有为这些方向给出全面的人类代表性或训练收益实验。
- 工作迁移：让模拟工单有清楚、模糊、后续修正等不同模式。把真实的形状、测量目标和审批范围作为环境约束，并让模拟用户在合适触发点才提供缺失输入。用小批真实纠错轨迹检验模拟覆盖。
- 最小验证：比较一次性交付全规格、脚本在关键点披露、基于真实交互重放三种。测 Agent 澄清对不对、是否无谓打断、能否响应目标变化。分开记录在模拟和真实交互里的结果。

### `arxiv:2609.01491`

- 原文：[GlossoGen，arXiv v1](https://arxiv.org/html/2609.01491v1)
- 范围：§3 角色、观察、评估边界，§4 通信可解释性与模型差异，§5 讨论。阅读围绕可审计的协作。
- 方法：让任务的两方持有互补信息，观察通信约束变化后约定能否跨轮使用，以及新加入者能否理解原有消息。作者用任务完成、与普通语言的差异和语义对应测量变化。

### `arxiv:2510.25779`

- 原文：[Magentic Marketplace，arXiv v1](https://arxiv.org/html/2510.25779v1)
- 范围：§3 市场与环境、§4 生成及验收，§5.1–5.2、§5.4 与 §6。仅用排序、效用和防御性评估结果。
- 方法：用合成顾客和商家构造可重复搜索、沟通和选择的环境，预先定义顾客的可行条件和效用。通过理想检索、词法检索、信息不全等对照，定位瓶颈在找候选还是选候选。
- 证据及边界：受控顺序实验中不同模型对首个到达的提议有明显偏好，部分设置下占 60–100%。GPT-4o 在一个市场中由 3 个候选扩展到 100 个时效用下降 4.3%。合成静态市场的任务、搜索和效用假设限制外推。
- 工作迁移：比较开源框架配置、算法和算子候选时，先给精度、硬件及 SLO 的硬条件。设固定收集窗口再比较合格结果，保留到达顺序。即使早返回可行候选，也对质量和成本做一致比较。
- 最小验证：给同一批候选交换顺序和到达时刻，测最终选择是否变化。再用理想召回与真实检索对照，记录丢失有效候选、选错候选和选优成本。必要时对召回和排序分别改进。

### `arxiv:2304.03442`

- 原文：[Generative Agents，arXiv v2](https://arxiv.org/html/2304.03442v2)
- 范围：§3 模拟环境与交互，§4 记忆、反思、计划及更新，§6–7 消融和社区行为，§8 限制。
- 方法：观察加入记忆流，检索综合相关性、重要性和时间。模型从观察生成高层反思，再将长计划分层拆解为短行动。新观察可触发计划调整。独立访谈评估人物行为，连续模拟观察群体结果。
- 证据及边界：25 个角色在 Smallville 模拟两天。100 名参与者比较同一角色不同架构和一份众包写作的访谈回复。完整架构的可信感高于消融。目标是行为是否可信。评价不能说明模型能预测某个真实同事或能提高技术任务成功率。
- 工作迁移：为长时间调优保存原始事件、带证据的总结和未来步骤。新 trace 反驳历史假设时调整计划。优先让事实链接到工具产物，降低摘要在跨会话使用时反复强化旧误判。
- 最小验证：用同一任务回放比较事件记录、增加摘要、增加计划状态三种。插入一条与旧总结冲突的新证据，测是否改判，是否减少重复运行，并跟踪错误摘要被沿用的比例。

### `https://cmu-agents.com/slides/lecture-15-orchestration-and-monitoring.pdf`

- 原文：[CMU L15，Orchestration and monitoring，课程站官方 PDF](https://www.cmu-agents.com/slides/lecture-15-orchestration-and-monitoring.pdf)
- 范围：L18 p.7 链接的无 www 入口未返回文件。读取课程快照哈希一致的官方 L15 缓存 39 页文字，重点 p.7–22 与 p.25–36。
- 方法：流程图节点交换显式状态。条件转移根据观察、分类和审批结果选路径。保存成功节点的结果和执行 ID，恢复时只重做必要步骤。监控结合单节点测试、图的集成测试、成对比较轨迹和对异常簇的人工复核。

- 最小验证：在已完成编译后注入短暂失败和人工改参，核对是否复用可用结果、何时需要重建、是否二次提交作业。对分类单测和实际流转分别验证。
