# L06、L20 深读 · 复现环境、验证器和工具迭代

本批细读六项登记来源的正文选段。范围从源码定位到测试数据，再到多次改动后的验收。列出的试验均为本地设计建议。

### `arxiv:2505.22954v3`

- 原文：[Darwin Gödel Machine: Open-Ended Evolution of Self-Improving Agents](https://arxiv.org/html/2505.22954v3)
- 范围：arXiv v3。细读 §§3–6，核对 Figure 2、Figure 4、Appendix A.1 的对照和 Appendix E.1 的成本定位。未阅读全部代码与提示附录。
- 机制：固定基础模型，在隔离环境中试验编码工具和流程的不同版本。每轮可从归档中取先前版本，按任务测试复验。报告的 SWE-bench 结果从 20.0% 到 50.0%。Polyglot 的筛选子集与最终完整集分开报告。作者同时指出 SWE-bench 单次实验约两周，API 成本高。公开结果依赖选出的基准、模型和预算。
- 改变的动作：为 profiler 分析或运行恢复流程保留可比较的工具版本、失败日志、改动边界和回放成绩。先在同一版本的目标项目上评价一个工具变更，再到另一批次或模型上复测。用便宜的预检淘汰不可执行的改动，避免把分支数量当作工作收益。
- 推翻条件：同预算比较人工小改动、固定流程和分支试验。若独立案例上无增益，或改动只优化了评估分数、增加后续维护，则保留原流程。功能、资源和隔离要求应与任务分数一起验收。

### `arxiv:2503.09089`

- 原文：[LocAgent: Graph-Guided LLM Agents for Code Localization](https://arxiv.org/html/2503.09089v2)
- 范围：arXiv v2。细读 §§3.1–3.3、§4.1、§§5.3–5.8 与 Limitations。核对 Tables 6–8 的定位、消融和修复对照。
- 机制：将 Python 文件、类和函数表示为图节点，保留包含、导入、继承和调用等关系。工具按实体查找，再按关系和深度查邻居。多跳消融对函数级定位影响较大。Table 8 中在相同 Claude 编辑器和 Agentless 编辑方法下，LocAgent 的文件 Acc@5 为 73.36%，原定位法为 58.39%。最终 Pass@1 从 26.31% 到 27.92%，定位增益与修复增益大小不同。
- 改变的动作：在 vLLM 的定位任务中，先从日志里的调度方法、请求状态和测试名查确切定义，再看调用链和状态写入点。只有直接搜索经常定位错时，才比较可复用代码索引。对于 CUDA 或 Python 动态分派，必要时用 trace、运行态注册表或生成源码补足静态边。
- 推翻条件：固定源码和时间，对比工程师搜索、普通关键词搜索和索引辅助。分别记录是否命中首个状态分歧、是否选到复现实验、最终是否通过独立验证。若索引只提高文件命中率，或代码边在目标版本上经常不完整，先保留直接搜索加动态证据。

### `arxiv:2504.07164`

- 原文：[R2E-Gym: Procedural Environments and Hybrid Verifiers for Scaling Open-Weights SWE Agents](https://arxiv.org/html/2504.07164v1)
- 范围：arXiv v1。细读 §2 的可执行环境、§3.1、§§4.1–4.4 和 §6，核对 Figures 4–7 与 Best@26 的对照。
- 机制：从有对应执行环境的历史提交收集或补写 fail-to-pass 测试，再结合失败轨迹反向整理问题描述。补丁选择比较测试运行与看轨迹的模型评分。SWE-bench Verified 的同一 26 条候选池中，理想 Pass@26 为 64.4%。只用执行与只用学习评分的 Best@K 分别停在 43.7% 和 42.8% 左右，混合后 Best@26 为 51.0%。消融发现测试区分力有限，模型评分可能被轨迹中的自我评价措辞影响。
- 改变的动作：把编译、正确性、有效计时和置信判断分开。可用模型给「下一项观测有无判别力」排序，将程序不变量与运行证据交给可复查的检查。对便宜但区分力有限的检查保留多个可行项，避免让同一模型的自信描述充当结论。
- 推翻条件：固定候选与工具预算，比较执行筛选、仅评价、混合。将原始结果保持不变并改写说明措辞，检查排序是否因此变化。若混合引入的额外误判、误拦和成本超过减少的错误，保留简单验证。

### `arxiv:2504.21798`

- 原文：[SWE-smith: Scaling Data for Software Engineering Agents](https://arxiv.org/html/2504.21798v2)
- 范围：arXiv v2。细读 §§2.1–2.2、§3、§§4.1–4.2 与 §6。核对 Tables 1、3 的分母、生成成本和独立测试口径。
- 机制：每个 Python 仓库先建可执行环境，再从单一版本派生不同问题。对照原版与改版测试结果，筛出有效任务，并用原始结果为问题描述提供依据。论文记录 128 个仓库、50,137 个任务，最终训练轨迹为 5,016 条。简单重复的轨迹被限量，原文还比较了只针对 SymPy 训练的本地收益和通用性能变化。
- 改变的动作：若需要生成调优助手的评估数据，从稳定 benchmark 和快照构造可复查的变体，例如顺序漂移、错误 workload 或运行分阶段失败。每个变体要有已知的行为变化和对应的预期判断。控制同一模板的重复数，把自然历史案例作为独立测试。先验证是否能帮助工作，之后再判断是否需要训练。
- 推翻条件：若模型在合成题上的提升不迁移到独立运行记录，或只学习辨认模板痕迹，则减少合成比例。若已有固定预检拦住这类错误，就优先保留规则。论文的 Python 实例与成本无法外推到多 GPU 调优任务。

### `arxiv:2603.13428`

- 原文：[SWE-Milestone: Evaluating AI Agents on Continuous Software Evolution](https://arxiv.org/html/2603.13428v4)
- 范围：arXiv v4。细读 §§3.1–3.3、§§4.1–4.3、§§5.1–5.6 和 Limitations。核对独立与连续任务设置、测试状态定义和回归分析。
- 机制：从提交历史构造有依赖的里程碑，持续模式让 Agent 继承自己的修改，独立模式每题从参考快照开始。度量分开记录新需求对应的 fail-to-pass、既有的 pass-to-pass 回归，以及完整解决率。论文报告独立里程碑整体分数超过 80%，连续场景为 38.03%。局部用例能通过时，前序错误和后续回归仍可能累积。结果依赖可执行测试充分的仓库和该研究选出的依赖图。
- 改变的动作：评估调优助手时，加入保留旧改动的后续任务。例如先改变 vLLM 调度或缓存配置，再检查另一组 workload 能否继续通过，随后遇到框架升级再运行。跟踪第一处失效及之后受影响的实验，单列既有正确性、性能和可恢复性。
- 推翻条件：若独立回放和连续回放的差异来自测试环境漂移，先修复重放环境。若长期行为仍稳定，单次选实验即可覆盖当前任务；若回归集中在前次未确认的前提，改用阶段验收或显式保存恢复点。

### `arxiv:2605.03546`

- 原文：[ProgramBench: Can Language Models Rebuild Programs From Scratch?](https://arxiv.org/html/2605.03546v1)
- 范围：arXiv v1。细读 §§2.1–2.4、§§3–4、§5.1 和 Appendix A.3 的测试构造与断言检查。核对 200 题和评估分母。
- 机制：提供可执行参考程序及使用文档，用外部可观察行为评估新实现。测试组在参考程序上先核查重复性，并检查简单无效的程序能否蒙混通过。200 个任务、9 个被测模型中，无模型完整通过一题，最高的模型仅在 3% 的任务通过至少 95% 测试。这是从零复现程序的口径，范围大于局部补丁。
- 改变的动作：用框架行为契约评价可替换实现。算子按参考输出、容差、shape、layout 和错误条件核对。服务比较保持接口和外部行为，同时用同条件测性能。用空实现、近似变体和边界错误检验测试是否有区分力。只有任务确实需要重写时才扩大到系统级行为。
- 推翻条件：若新旧实现因测试不必要地要求相同内部细节而出现误拦，回到可观察契约。若错误变体也能通过，提高测试强度。若目标只改局部性能，完整重建基准的高成本会影响优先级，应比较局部测试加代表性端到端对照。

## 对本地工作比较的影响

先确认能不能用旧环境复现目标问题，再评价工具能不能更快找到正确的状态和下一次观测。生成的数据用已知错误检验区分力，真实历史案例用来确认迁移。对于会持续修改同一框架的方案，加一组后续工作，核查旧结论的有效条件和旧行为是否随修改保留。
