### `arxiv:2605.06639`

- 原文：[Recursive Agent Optimization v2](https://arxiv.org/html/2605.06639v2)
- 范围：§§2.1–2.2、3.1–3.3、4–5，核对 Table 1–3 的任务与条件，以及 Figure 8–9 的奖励消融。
- **方法。** 同一策略承担根任务和子任务。子任务有局部奖励。父节点可得到按直接子任务成功比例计算的委派奖励。论文按深度调整训练权重，以免采样时大量节点主导更新。TextCraft-Synth 用已知检查器，Oolong-Real 和 DeepDive 的部分子任务使用模型评审。
- **证据与边界。** DeepDive 的 50 个留出任务上，单 Agent 和递归 Agent 成功率为 0.24 和 0.40。时长和步数只在双方都解决的任务中比较。TextCraft-Synth 的一个消融用成功子任务数量给奖励，导致更多不必要委派、用时上升并在第 40 步后使成功率下降。训练设定不能证明增加并发一定省时。
- **工作动作。** 只有能用边界清楚的证据独立回答的问题才拆出去，例如分别定位编译前提和核对计时分母。每个子任务回传原始来源、已确认结论和未知项。根任务检查子结果是否改变后续决策。
- **验证。** 在同样工具和成本上限下比较单流程、固定并行分组和递归分解。报告全样本成功与时长，另给共同成功子集结果。按有效证据和错动作计分。若委派数量增加而没有新增决定性证据，先采用较浅的分解。

### `arxiv:2605.14290`

- 原文：[Web Agents Should Adopt the Plan-Then-Execute Paradigm v2](https://arxiv.org/html/2605.14290v2)
- 范围：§§IV–VI、VII 的工具契约、编译与执行、Table I 人工覆盖分析及预先编排的限制。只阅读用于防御和工作流程的设计。
- **方法。** 先依用户目标与有类型的工具接口编译任务流程。运行时输入可以给既有分支绑定参数。需要语义判断时，调用仅返回符合 schema 的模型子程序。工具调用与可修改状态的逻辑由既有流程控制。
- **证据与边界。** 假设六个 WebArena 站点具备完整可信 API，人工检查 860 项任务，699 项可写成无需运行时模型子程序的流程。其余 161 项需要运行时模型解释。这是人工可行性估计。原站点 Postmill 的原生 API 当时只覆盖 129 项中约三分之一，且论文未用端到端 Agent 实测这些成功率。
- **工作动作。** 对固定 benchmark 把输入解析、正确性、资源条件和清洁测量写成可审阅流程。允许新的 telemetry 选中预设分支。超出已知条件时，用受控只读调查找缺失状态，保留已完成记录和用户目标。
- **验证。** 给固定流程与可分支调查相同的工具覆盖。分开测已知路径、工具缺失、以及新状态需要查其它证据的任务。统计由于工具缺口而停住的比例。若差距主要是可用 API 的覆盖，先补接口。若接口齐备仍需解释新观测，再比较动态判断。

### `arxiv:2512.24601`

- 原文：[Recursive Language Models v3](https://arxiv.org/html/2512.24601v3)
- 范围：§§2、3.1–3.2、4、5、7 及 Appendix B、F 的失败与成本入口。核对 Table 1 的长上下文对照。
- **方法。** 长输入放在外部程序状态中。主模型读结构、搜索和切分，按需调用子模型。可将中间结果留在变量里，避免把完整文件重复放进根上下文。论文比较直接模型、压缩、检索以及允许程序处理的配置。
- **证据与边界。** OOLONG-Pairs 上，两个直接模型的 F1 均不高于 0.1%。对应一层递归配置分别为 58.0% 和 23.1%。该数据需要密集地组合成对证据。RLM 成本的中位数较低和均值较高可以同时出现，因为少量任务触发长尾子调用。实验使用阻塞式调用，实际墙钟仍受实现和服务影响。
- **工作动作。** 先程序化筛选大 trace 或多份 run 日志。将同请求或同轮次的证据放在一组，并保留跨组关联键。在解析得到候选但还无法解释机制时，再把选段交给模型。避免每个字段触发一次子模型请求。
- **验证。** 先用同一原始记录比较整段输入、按请求取证和程序聚合加模型解释。选择一个需跨 rank 关联和一个适合单文件分块的案例。分别记录首次定位、重要条件遗漏、长尾调用、费用及错误下一步。若分组使关联错误增加，先改索引与关联键。

### `arxiv:2203.14465`

- 原文：[Self-Taught Reasoner，STaR v2](https://arxiv.org/html/2203.14465v2)
- 范围：§§3.1–3.2、4.1–4.4、5–6 的过滤、给答案后的理由生成、GPT-J 对照及失败边界。
- **方法。** 从少量示例启动模型，生成理由和答案，只用答案正确的样本进行微调。对于失败题，把正确答案提供给模型，让它再次生成理由。每轮用新的样本集从原预训练权重开始训练。
- **证据与边界。** CommonsenseQA dev 的 GPT-J 直接微调为 60.0%，STaR 无给答案环节为 68.8%，含给答案环节为 72.5%。Table 1 各行训练集使用比例不同。作者提醒，启动需要超过随机猜测的正确率。二元判断较容易碰巧答对，按最终答案过滤会留下一些错误理由。
- **工作动作。** 若要把研究轨迹做成示范，先筛掉只因看过最终日志才成立的理由。输入前缀固定在决策时点。要求目标动作引用当时已存在的证据，并解释其他观察会如何改变分支。生成材料与独立判断样本按项目分开。
- **验证。** 用同样的模型和证据比较仅保留最终正确的示范、以及另经人工核对中间证据的示范。用正反例检查碰巧猜对的动作。若依据不足的示范提高得分却增加错归因，就先修标注和评估。

### `arxiv:2410.05243`

- 原文：[UGround v3](https://arxiv.org/html/2410.05243v3)
- 范围：§§2.1–2.3、3.1–3.5、4，核对 Table 7–9 的在线任务、Figure 5 的错误归因和训练数据消融。
- **方法。** SeeAct-V 让 Planner 描述要找的元素，UGround 再把文字目标定位到截图坐标。训练例由网页合成的图像、指代表达和中心坐标组成。在线评估分开计关键节点完成与整个任务成功。
- **证据与边界。** Mind2Web-Live Table 7 中，GPT-4o 搭配 UGround 时关键节点完成率为 50.8%，高于文本对照的 47.6%，任务成功率为 19.2%，低于文本对照的 22.1%。实验界面与输入方式均有变化。对失败任务的归因显示，较常见的是 Planner 准确描述了错误对象。训练以网页为主，对长尾图标和桌面有局限。
- **工作动作。** trace 图中先要求说明要找哪个 rank、stream 和事件关系，再从画面定位。分别核查目标选择和定位。已有时间戳与结构化数据时，以它们复核图中发现。若目标事件本身选错，修正诊断假设优先于提高图中点选精度。
- **验证。** 在同一个 trace 中同时给目标正确的查询与可能误导的相邻事件。比较从图定位、从事件表定位和两者互证。记录目标选择准确率、对象匹配、最终归因和后续动作。若读图只改善位置识别，保留它作为补充证据。

### `arxiv:2402.01622`

- 原文：[TravelPlanner v4](https://arxiv.org/html/2402.01622v4)
- 范围：§§3.1–3.4、4.1–4.4、5，核对 Table 3–4 的两阶段与已知全部信息设置，以及 Micro/Macro 分母。
- **方法。** 模拟旅行规划区分环境信息、常识和显式硬约束。两阶段模式先从工具取得信息再规划，sole-planning 模式直接给必要材料。评估交付、单约束通过和同时满足全部约束。
- **证据与边界。** GPT-4-Turbo 的 ReAct 两阶段最终通过率为 0.6%。信息齐备模式仍有规划错误。单约束平均分高与整条计划失败可以同时发生。论文中的旅程验证器覆盖特定数据库、条件与任务。规则的环境数据和语义解析也需要核查。
- **工作动作。** 性能建议交付前逐条检查设备、硬件资源、模型、输入分布、精度、配对基线和正确性。给不同维度保留失败原因，并要求主要条件同时成立。先检查是材料未齐、值提取错误还是规划不满足约束。
- **验证。** 为相同优化意图给一份完整证据和一份只缺决定性约束的证据，测工具补证、解释正确及全部条件通过。单项通过率与整项验收分开。若计划即使拿到齐全输入仍不符合确定性约束，先增加可审查的前置检查。

### `arxiv:2502.15840`

- 原文：[Vending-Bench v1](https://arxiv.org/html/2502.15840v1)
- 范围：§§2.1–2.5、3.1–3.4、4，核对 Table 1 的五次运行、人工基线和模拟停止口径。
- **方法。** 模拟长期运营任务。Agent 跨多日管理库存、资金和沟通。提供草稿、键值和相似检索式记忆。测试记录最终净值、现有现金、停止销售前天数、动作历史及陷入循环。
- **证据与边界。** Sonnet 五次的平均净值为 2,217.93，最低 476。单次人工五小时基线为 844.05。人和模型样本数不同，无法从最小值估计人类长期方差。模型统一限制 2,000 条消息，各次实际模拟天数不同，净值还包含未售库存。
- **工作动作。** 跨日实验保留真正的完成条件、预算余额、已有有效基线、未决诊断和已确认终态。把可以复用的结果与仍需重新跑的部分分开。定期检查是否还在推进工作目标，并保留停止证据。
- **验证。** 用多份独立历史记录回放恢复，比较有无结构化状态，按任务完成、最差运行、空转和重提计分。各方案使用一致的实际时间或动作预算。若平均值上升伴随关键失败增多，先处理该失败阶段。

### `arxiv:2511.02208`

- 原文：[Training Proactive and Personalized LLM Agents，PPP v2](https://arxiv.org/html/2511.02208v2)
- 范围：§§3–6、7 的任务与奖励消融、§8 用户研究。核对 Table 1 的模拟评估和 Figure 9 的真人交互。
- **方法。** 把目标完成、提问成本和对用户偏好的遵守都纳入评估。UserVille 生成不同程度的含糊任务，并模拟用户回答。训练的多目标信号鼓励询问真正改变行动的信息。
- **证据与边界。** §8 的 33 人编程研究里，PPP-36B 的总体评分为 3.75，高于同基础 Seed-36B 的 3.45，接近 GPT-5 的 3.79。其报告的任务解决率仍低于 GPT-5。受访者既认可有用澄清，也提到泛问、过度设计和无信息时循环。交互成本的模拟与真实感受有差距。
- **工作动作。** 当缺失的目标、受影响 workload、GPU 或资源条件会改变实验排序时，先从已给资料取证。仍无法确定时只请求会改变选择的最小信息。低成本且可逆的检查可先完成，再带明确分叉请用户决定。
- **验证。** 把相同工程问题构造成关键信息齐全、缺一项会改变动作、以及缺非关键字段三种。比较固定澄清、先查已有证据、模型决定是否询问。测提问是否必要、工程师耗时、后续行动改正和完成率。若收益来自获取已有记录中的字段，先修检索。

## 跨来源判断

给计划足够信息以后，仍需单独检验约束是否同时成立、对象选择是否正确、以及新的观测能否改变下一步。固定工作流可先用于有明确工具和分支的步骤。比较动态调查时，保持工具、预算和可获得证据相同。给不同方法同样的终态和成本，完整报告所有运行，再检查共同成功子集。
