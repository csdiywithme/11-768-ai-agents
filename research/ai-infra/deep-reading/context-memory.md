# L3 上下文、注意力和服务调度

核验日期 2026-11-13。每项记录论文或文章所测条件，以及可在 AI Infra 工作中验证的下一步。此批覆盖 10 个登记来源。

### `arxiv:2311.04934`

- 原文：[Prompt Cache，arXiv v2](https://arxiv.org/html/2311.04934v2)
- 范围：§§3.1–3.4、4、5.1–5.2。核对图 2–3、质量表和文中对跨模块掩码的讨论。
- 机制与证据：PML 声明可复用文本模块。各模块按预分配的位置独立编码，跨模块注意力受掩码限制。导入时拼接对应 KV，新 token 可使用这些状态。对于必须相互解释的模块，作者提出联合编码以恢复跨模块注意力，增加缓存占用。图 3 使用约 5K token 的八个 LongBench 数据集和 RTX 4090、A40、A100。作者报告 CPU 侧模块带来 1.5–3 倍 TTFT 加速，GPU 侧为 5–10 倍。质量表中部分模型和任务的分数下降。
- 工程动作与反证：先用请求轨迹找内容稳定、语义独立的长段。将完整 prefill、相同前缀复用和模块拼接放进同一实验。记录重用频次、预计算摊销、跨设备复制、TTFT 和需要跨段理解的任务准确率。若缓存加载抵消 prefill 节省，或原始模块间的依赖导致关键判断改变，取消对应模块的独立复用。

### `arxiv:2606.13361`

- 原文：[Can I Buy Your KV Cache?，arXiv v1](https://arxiv.org/html/2606.13361v1)
- 范围：§§4–6、8–9。核对同前缀复用条件、成本式、表 1 和限制。
- 机制与证据：相同的因果模型、token 前缀、位置和掩码允许复用先前 KV，实际计算仍有浮点差异。作者使用 Apple M1 Pro 的 MPS 和 FP16 Qwen3-4B，贪心生成 24/24 token 相同，下一 token 最大 logit 差为 0.02。255–3774 token 的 8.6–49.7 倍是全量 prefill 对内存中已有 KV 的一次续算的计算时间比，取 5 次运行中位数，排除磁盘 I/O。单个 692 token 样本使用逐张量对称 int8 时，产物减半，FP16 路径的 32 个 token 中有 16 个一致。
- 工程动作与反证：记录模型和 tokenizer 版本、前缀 token 序列、位置、掩码、精度和 KV 格式。测本地冷加载、设备驻留和远程传输，以及未命中时的回退。先做任务正确性与下一 token 分布检查，再比较含读盘、传输与排队的端到端 TTFT。如果远程命中的耗时超过重算，或量化改变关键输出，缩小复用边界。

### `arxiv:2509.13313`

- 原文：[ReSum，arXiv v3](https://arxiv.org/html/2509.13313v3)
- 范围：§§3.1–3.3、4.1–4.4、附录 F。核对表 3、摘要触发算法、分段训练和资源开销。
- 机制与证据：轨迹达到阈值时，独立摘要模型按任务目标整理已有进展。后续上下文由原始问题和摘要恢复。ReSum-GRPO 将轨迹级优势分配给摘要分段中的可训练决策。表 3 使用 Tongyi-DeepResearch-30B-A3B。BrowseComp Pass@1 在 32K 条件下从 27.7% 到 34.5%，在 128K 条件下从 42.2% 到 44.5%。工具上限分别是 40、120。同一组内 ReAct 会因窗口耗尽提早终止，实际使用工具机会可以不同。论文另报告 ReSum-GRPO 训练时间约为比较方法的 1.5 倍。
- 工程动作与反证：长调优任务压缩时保留工作负载、硬件、基线、未证实假设、原始 profiler 路径与下一项排除实验。用固定工具、token 和时间预算回放，单独测每次压缩后的约束恢复率、重复试验次数和最终诊断。若精简状态导致重跑已排除方案，或丢掉关键数值的单位和来源，调整保存内容或使用外部结构化工单。

### `arxiv:2310.01889`

- 原文：[Ring Attention，arXiv v4](https://arxiv.org/html/2310.01889v4)
- 范围：§§2–3、5.1–5.2、表 2–4 和附录的推理说明。以表 2 记录互连条件。
- 机制与证据：各设备保留本地 Q，环形轮转 K/V 块，用分块 softmax 累加精确注意力。只有每块计算时间足以覆盖传输时，通信才可被隐藏。表 2 按带宽和 FLOPS 估算 A100 NVLink 与文中 A100 InfiniBand 配置所需最短序列约 6.2K 与 149.5K。表 3 在 8×A100 NVLink、7B、FSDP 的训练条件下，内存高效 attention 加 FFN 基线最多支持 32K，Ring Attention 为 256K，批总 token 数保持一致。
- 工程动作与反证：当长序列先触及显存上限时，固定每批总 token 数、模型和精度，改变上下文分片和 GPU 拓扑。以实际通信带宽、重叠区间、峰值显存和每步吞吐判定。如果计算外通信暴露使步时超预算，将这项改动限定在确实需要长序列容量的任务，或测其他切分。

### `arxiv:2412.06464`

- 原文：[Gated Delta Networks，arXiv v3](https://arxiv.org/html/2412.06464v3)
- 范围：§§2.1–2.2、3.1–3.4、4。核对表 2、表 5、图 3 的任务、训练条件和对照。
- 机制与证据：输入控制的衰减项调节旧状态保留，delta 更新基于当前键和预测残差修正关联值。分块计算使训练可利用矩阵乘法并把递推限制在块边界。表 2 在 1.3B 模型的合成检索中，8K S-NIAH-1 的 DeltaNet 为 98.8，Gated DeltaNet 为 91.8。4K S-NIAH-2 的两者分别为 18.6 和 92.2，说明清除干扰与保留久远证据有不同代价。图 3 的单 H100 比较是训练吞吐。
- 工程动作与反证：对 recurrent/hybrid serving 单独测 recurrent state、注意力 KV、decode 数据搬运与 prefill 吞吐。构造重复前缀、短近线索、长距精确 ID 和相似干扰的请求。若固定大小状态节省显存但长距离定位无法达到质量目标，比较局部注意力或少数全局层的质量和成本。

### `arxiv:2510.26692`

- 原文：[Kimi Linear，arXiv v2](https://arxiv.org/html/2510.26692v2)
- 范围：§§2.2–3.2、4、5.2、5.6、7.2。核对图 7 的模型、输入长度、指标和 batch。
- 机制与证据：Kimi Delta Attention 使用逐通道的遗忘门和适合块运算的形式。模型每三层 KDA 接一层全局 MLA，以给精确的长距离检索保留通路。§5.6 的 48B、相同层数和 head 数、batch 1 对照中，512K 与 1M 的 prefill 比全 MLA 分别快 2.3 与 2.9 倍，短区间 4K–16K 相近。
- 工程动作与反证：在支持该架构的后端，分别量化 KDA 状态和全局层 KV 的显存及数据搬运。检查不同 prompt 长度、并发和输出长度下端到端 TTFT、TPOT 和正确性。用精确代码符号检索或跨日志关联作为长距检查。若主要生产请求在短长度，或 MLA 层、通信和排队已经主导尾延迟，重新评估优化优先级。

### `arxiv:2512.02556`

- 原文：[DeepSeek-V3.2，arXiv v1](https://arxiv.org/html/2512.02556v1)
- 范围：§§2.1–2.3、3.2.1、4.4、5。核对 DSA 训练两阶段和图 3 估价依据。
- 机制与证据：轻量 indexer 对候选历史 token 打分，选 top-k 供主注意力。对长度 L 的 prefill，主注意力从 O(L²) 到 O(Lk)，全文 indexer 仍有 O(L²) 打分。作者先单训 indexer，再按稀疏注意力继续训练主模型，文中稀疏训练每个 query 选 2048 个 token。H800 图 3 是部署服务基准按指定 GPU 租价折算的成本，短 prefill 使用专门的 masked MHA 模拟 DSA。
- 工程动作与反证：在相同模型和已验证后端中，将 indexer、top-k、gather、主注意力和通信列入同一个时间线。跨长度、batch、k 跟踪 TTFT、TPOT、吞吐和质量。若 indexer 或 gather 的新增时间抵消主注意力收益，找有效长度的切换点或调整优化目标。把架构和模型训练的收益与 kernel 改动分开测。

### `arxiv:2305.13245`

- 原文：[GQA，arXiv v3](https://arxiv.org/html/2305.13245v3)
- 范围：§§2.1–2.2、3.1–3.3、表 1、图 5–6。核对微调和 TPU 测时条件。
- 机制与证据：多组 query heads 各自共享一组 K/V。每组取一个共享头时介于 MHA 和 MQA 的状态大小之间。论文先均值池化已有 T5.1.1 检查点的 K/V 头，再使用原预训练约 5% 的计算量继续训练。T5-XXL GQA-8 的质量接近 MHA-XXL，速度接近 MQA。测试在 8 个 TPUv4 上按模型分别优化并行配置和适配的 batch，图 6 输入 2048、输出 512。
- 工程动作与反证：先核实际每设备 KV heads、dtype、layout、TP 切分或复制，按 profiler 验证字节量。比较 KV 驻留、带宽、batch 上限与 decode 时延。如果 TP 把少数 KV 头复制给多个 rank，或调度同步主导时间，重新估计 GQA 对实际服务的收益。用现有 GQA 权重做 kernel 实验时保持模型不变。

### `https://lmsys.org/blog/2024-12-04-sglang-v0-4/`

- 原文：[SGLang v0.4，LMSYS 官方发布说明](https://www.lmsys.org/blog/2024-12-04-sglang-v0-4/)
- 范围：2024-12-04 发布说明，CPU/GPU 重叠调度、缓存路由、DeepSeek DP attention、XGrammar 四节及所列基准命令。
- 机制与证据：CPU 调度预备后一批元数据，使用 future tokens 和 CUDA events 管理与 GPU 计算的依赖。文章 Nsight 图仅显示 Triton 后端的 5 个 decode 批次，文中说明 FlashInfer 仍有短间隙。缓存路由用近似 radix tree 估计各 worker 前缀命中，同时避免负载过度偏斜。8×A100 80GB、Llama 3.1 8B、均衡合成长前缀组的路由测试，命中率由 20% 到 75%，吞吐从 82,665 到 158,596 token/s。DP attention 通过减少 MLA KV 跨卡重复为 batch 腾出显存，同时引入 MoE 前后的数据重排。XGrammar 的倍数属于结构化输出基准。
- 工程动作与反证：先看 Nsight Systems 的 GPU 空档是否伴随 CPU 调度和同步，再决定改调度或算子。路由消融固定模型、硬件、到达序列和采样参数，对均衡与偏斜前缀分别记录命中率、worker 队列、p95/p99 TTFT 和吞吐。若命中上升但热门 worker 排队抵消收益，应调整负载约束或匹配优先级。
