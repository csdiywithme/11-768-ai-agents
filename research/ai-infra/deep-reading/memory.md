# L4 记忆与技能。保存哪些经验，怎样验证复用

核验日期 2026-11-13。八个来源均读取论文正文的机制、实验和局限选段。讲次位置按课程引用索引登记。课表给的是无版本号的 arXiv 入口，下文链接固定本次核对的版本。各论文结果都属于作者实验。性能工程的迁移与对照是待检验的设计。

### `arxiv:2310.08560`

- 原文：[MemGPT v2](https://arxiv.org/html/2310.08560v2)
- 范围：L3 p.48 与 L4 p.17。读 §§2.1–2.4 的上下文分层、队列溢出与工具链，§§3.1.1、3.2.1–3.2.2 的设置与结果，Table 2、Fig. 5。附录提示词未逐条核查。
- 机制：常驻上下文含只读指令、可编辑工作区和近期消息队列。到警戒阈值先提醒保存，到上限才淘汰并递归总结。原消息保留在 recall storage。模型用分页工具取回旧消息或档案，工具结果和错误都重新进入上下文。
- 证据与条件：作者的 DMR 使用 MSC 五轮对话和模型生成的窄答案问题。GPT-4 的准确率为 32.1% 和 92.5%，后者可分页读取原对话，前者使用压缩摘要。两个条件的可用信息不同。文档 QA 只抽取 50 个 NQ-Open 问题，报告还依赖外部检索和模型判分。
- 工程动作与反证：恢复性能调查时，在常驻状态保留目标、配置指纹、当前假设、最后一项可区分观察和原始产物路径。长日志按需读取。把同一个历史前缀移出常驻上下文，比较长上下文、递归摘要、可取回原片段三种做法。观察是否恢复了 profiler 与干净计时的区别，以及下一步是否保持一致。若原片段的按需检索没有改善决策，优先保持简短状态记录。
- 同站扩展：Letta V1 SDK 的 Memory blocks 文档区分常驻可写和只读块，并明确并发更新同块可能发生覆盖。调研中的共享状态可按写入者保留事件记录，保留源日志。此处只核对文档的 Read-only blocks 和 updating 说明，未试运行 SDK。 [Letta Memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks)

### `arxiv:2504.19413`

- 原文：[Mem0 v1](https://arxiv.org/html/2504.19413v1)
- 范围：L4 p.18。读 §§2.1–2.2、3.1–3.3、4.1–4.5 和 §5，核查 Table 2 的检索与总延迟、基线范围及评估口径。
- 机制：从新消息对、近期消息与异步刷新摘要抽取候选事实，再检索相近记忆，让模型判定新增、更新、删除或无操作。图变体从文本生成实体和关系三元组，结合实体邻接与语义匹配取回关系。实验中近期消息和更新候选都取 10。
- 证据与条件：LOCOMO 含 10 个长对话，实验排除了识别不可回答问题的对抗类别。Table 2 的总体模型判分，全文上下文为 72.90%，Mem0 为 66.88%，图变体为 68.44%。总延迟 p95 分别为 17.117、1.440、2.590 秒。图变体的时间类分数更高，单跳和多跳未超过文本变体。这个取舍依赖模型、索引、硬件和任务。
- 工程动作与反证：同一 run ID 的摘要修订要保留时间和来源。不同 GPU、源码或负载的结果分别落记录，避免把新结果覆盖到相似旧记录。先比较按 run ID 和配置指纹过滤的索引、语义检索、带依赖关系检索。用跨版本、同名任务与结果冲突的盲例，报告错配率、条件召回和总用时。若过滤已解决版本错配，图检索需要在真实跨 run 问题上证明增量。
- 同站扩展：当前官方 Search Memory 文档给出过滤、阈值和条数等控制项。应用时要检查其平台与 SDK 版本，并验证这些过滤是否能按实际运行指纹表达。读取 How Mem0 Searches Memory 和 Key terms。 [Mem0 Search Memory](https://docs.mem0.ai/core-concepts/memory-operations/search)

### `arxiv:2303.11366`

- 原文：[Reflexion v4](https://arxiv.org/html/2303.11366v4)
- 范围：L4 p.19、L20 pp.18–19。读 §§3、4.1–4.3、5 及附录 B.1。核对 Rust 消融 Table 3 和 WebShop 的负结果。
- 机制：同一任务内，执行者产生轨迹，评估者提供结果，反思模块把轨迹与结果变成下一轮的短提示。实验用滑动窗口保存反思。编程任务允许模型写测试，语法有效检查只能确认测试能被解析。
- 证据与条件：50 个最难 HumanEval Rust 任务中，基础模型 60%，仅反思 52%，仅生成测试 60%，两者合用 68%。作者讨论了错误测试带来的真假阳性。WebShop 的 100 个环境中运行四轮后无明显改善，作者据此指出反思可能困在相似探索路径。
- 工程动作与反证：在同一实验重试前保存失败阶段、原始信号、可能原因和可区分的下一动作。比较直接重试、根据结构化阶段结果处理、由模型生成反思三种条件。若新方案还在重复相同调用，或无法增加可区分的观测，应当停止这类重试。把可复查的事实从反思假设中分开，避免把硬件失败或超时写成性能退化。

- 范围：L4 p.20。读 §§4.1–4.4、5.1–5.6 与 §6。核对四折评估、Table 1–3 和学习、评估分开的位置。
- 机制：在训练任务内用反思收集多次尝试。对同任务的成功与失败做对照，也从跨任务成功轨迹找共性。抽取的规则可增加、编辑、加权或降权。评估时给规则和检索到的成功示范。任务内纠错与跨任务积累是不同阶段。
- 证据与条件：作者 Table 3 的 HotpotQA 对照中，ReAct 28%，ExpeL 39%，抽取时再加入原始反思的变体为 29%。作者给出反思可能带入误判的解释。HotpotQA 到 FEVER 的迁移共享 Wikipedia 工具，ReAct 为 63%，带目标任务示范的迁移为 70%。实验使用文本观察和特定版本的闭源模型。
- 工程动作与反证：以相同故障目标的失败和成功日志做配对。例如并列读取观察器超时后原运行仍活动的证据，与服务端确认为无容器的终态。记录两者决定重连还是重排的条件。用未参与抽取的新调用和新版本回放，比较规则、配对示范、以及两者合用。若新增规则只在原案例有效，限制规则范围或保留原始示范。

### `arxiv:2504.06821`

- 范围：L4 pp.29–30、32–34。读 §§2.1–2.3、3.1–3.3、4–5、7，核查 Table 1、3、6 和验证用前缀。
- 机制：从模型判为成功的轨迹抽取 Python 技能。把原轨迹中对应低层动作替换为技能调用，截掉可能直接交付正确答案的尾部动作，再执行并续写。通过条件包括完成目标、确实调用新技能、调用改变环境。验证后的程序也可改写成文字加入上下文。
- 证据与条件：WebArena 812 个任务，同为 Claude 3.5 Sonnet 的 vanilla、AWM、ASI 总成功率为 32.7%、36.3%、40.4%。购物站消融中，已验证技能作为文字加入上下文为 39.0%，作为可执行动作是 40.1%。未验证文字为 32.6%。跨站示例的排序控件变更使已验证技能失效。跨站采样以信息检索为主。

### `arxiv:2509.25140`

- 原文：[ReasoningBank v2](https://arxiv.org/html/2509.25140v2)
- 范围：L4 pp.38–41。读 §§3.1–3.3、4.1–4.4、§5，附录 A.2、C.1–C.2、E。核查 Tables 1–2、5 和 Fig. 7、8、13。
- 机制：每轮检索相似任务的经验。用模型对新轨迹判成功或失败，再抽取带标题、描述、内容的策略。默认只取一个历史经验，抽取至多三个记忆条目，并追加保存原轨迹。MaTTS 可比较同题并行轨迹，或利用一条轨迹的连续修订，得到更有区分力的记忆候选。
- 证据与条件：在 Gemini 2.5 Flash 的 WebArena Shopping 子集，作者报告只用成功轨迹的 46.5%，加入失败后 49.7%。从一个经验增到四个，成功率从 49.7% 降至 44.4%。附录的 token 对照中，无记忆为每轨迹约 50.8k token，ReasoningBank 含评审、抽取后为 53.1k。模型判分噪声对照是在一个子集按已知真值随机翻标签，无法代表故障类型相关的误判。
- 工程动作与反证：保存「出现什么观测时改选哪条实验」及原始证据。把编译失败、运行未启动、正确性淘汰、计时失稳、性能回归分别记录。用硬件、软件版本和任务约束筛选少量经验。比较不读历史、只读成功、加入带原始失败证据的经验。若失败经验增加错误重试或跨版本错判，先修错误类型和相关性判断，再扩大记忆。

### `arxiv:2606.15390`

- 原文：[Not All Skills Help v1](https://arxiv.org/html/2606.15390v1)
- 范围：L4 p.42。读 §§2.1–2.3、3.1–3.4、5，附录 A.3、K.1–K.2。核对开发集与测试集分隔、Table 1、附录的统计功效与零增益结果。
- 机制：在留出开发集为技能做随机遮蔽，比较含有和没有该技能时的任务成功。估计的是在该抽样组合下的边际效果。对效果跨任务变化的技能先拆适用条件，再退役低影响和合并近似项。遇到新任务时从相近开发例估计遮蔽。部分操作模板有保留规则。
- 证据与条件：GPT-5.1 在 AppWorld challenge 上，无技能为 52.5%，ACE 为 49.9%，Assay 为 66.4%。同一方法在 τ-bench 上对 GPT-5.1 与 Sonnet 4.5 无改善。每模型 12 个随机遮蔽乘 15 个开发任务，合计 180 条轨迹。附录 K.1 在该参数下，对绝对 0.30 的单格效应检验只有 38.5% 功效。逐技能解释需要重复和独立对照。
- 工程动作与反证：给「高噪声时先做 A/A」等建议写触发条件，并记录工具可用性和候选接近程度。在新形状或新任务中，同一模型、同一前缀和预算下比较无技能、全量、条件启用。按 GPU 成本、主动工时和关键错误分层。若额外检查只拖慢已稳定的路径，优先缩小触发条件。若小样本无法区分，不为单个技能定通用结论。

## 可直接接入现有验证设计

- 同一次实验恢复和跨项目迁移分别试。前者检查能否取回原记录。后者检查能否找到在新硬件、版本或负载上仍适用的经验。
- 固定同一模型与预算，比较原始证据、证据加配对示范、证据加一条带适用条件的经验。用同一隐藏结局的决策前缀和留出项目。已有案例可校准判分。
- 给每条经验保存原始依据和失效条件。先用编译、正确性、计时协议和运行终态定事实。模型提取的机制猜测还需独立观察。若规则或脚本达到相同效果，优先记录其覆盖范围和维护代价。
