# L5 规划补读 · 状态反馈、程序接口与多轮可靠性

2026-11-13 阅读批次。下面区分原文实验、对 AI Infra 工作的推断及本地验证设计。实验结果按原文的模型、任务和分母解释。

### `arxiv:2305.04091`

- 原文：[Plan-and-Solve Prompting v3](https://arxiv.org/html/2305.04091v3)
- 范围：§§2–4、7，核对 Table 2 的算术任务、Table 6 的错因及使用单一旧模型的限制。
- **方法。** 零样本 PS 先形成解决方案，再执行各步。PS+ 加入抽取变量和单位、计算中间量等指令。生成推理过程后用单独提示抽取答案。这里的计划和执行是同一推理生成中的两个阶段。
- **证据与边界。** 100 个 GSM8K 示例的错因分析中，PS+ 的计算错误为 5%，缺步骤错误为 7%，相比 Zero-shot CoT 的 7%、12% 更少。语义误解仍是 27%。作者使用特定旧 GPT-3 设置和十个推理数据集。这组证据不能判断计划能否读取新观测并改变动作。
- **工作动作。** 对 GPU 测量先填比较对象、单位、分母、聚合方式、正确性门槛，再选择如何求出差异。适合先改善可预见的缺字段和漏步骤。遇到“优化吞吐”实际意指提高特定 SLO 下的 goodput 时，应明确目标后再分析。
- **验证。** 对照直接解释、填约束再解释、用脚本读取与计算三种做法。注入多个 token 分母和错位的毫秒/微秒字段。分别评分漏步骤、错误算术和目标误读。如果语义错因占主，优先修目标说明与评审输入。计算可稳定形式化时测脚本是否已解决问题。

### `arxiv:2209.07753`

- 原文：[Code as Policies v4](https://arxiv.org/html/2209.07753v4)
- 范围：§§III.A–III.D、IV.A、IV.D、V 和 HumanEval 表。读程序如何组合控制原语及失败适用范围。
- **方法。** 由模型生成程序把语言目标变成控制策略。程序可以使用已有感知和控制函数，读取运行状态，做几何、循环或条件逻辑。生成器还可为未定义函数递归生成实现。底层既有接口和提示示例决定程序能做到什么。
- **证据与边界。** 作者的 HumanEval 附录指出，164 道题中只有约 6.5% 触发层次生成，该子集中两种扁平基线为 44%、层次生成 56%。样本很少。作者也指出机器人任务假定指令可行、未事先验证响应正确，在新空间要求上会脆弱。
- **工作动作。** 让模型组合已有的只读 trace 查询、配对计时统计和运行状态检查。对 repeat、rank 聚合、单位转换和停止分支用可审阅的程序表示。保留低层函数的版本及输入数据。发现某个动作没有受支持接口时，记录依赖缺口，由人工或单独测试补齐。
- **验证。** 使用已经存在的两类 JSON/SQLite 数据，对照自然语言过程、复用已知函数和模型生成自由查询。先检查每步结果，再检查是否解决任务与人工审阅成本。在样例中加入新的 schema 和无效路径。若程序跨 schema 时不断缺必要原语，缩小开放生成范围并先建立可测试的适配。

### `arxiv:2210.02875`

- 原文：[Binder v2](https://arxiv.org/html/2210.02875v2)
- 范围：§§2.1–2.3、3.1–3.2、4 和附录 E 的错因入口。核对 WikiTQ、TabFact 和 Table 4 的误差样本。
- **方法。** 扩展 SQL 或 Python 的表示，在符号语言表达不够时调用神经模型。先解析程序，逐个计算模型调用，再将输出写回变量，由普通解释器执行。模型解析与模型执行都可能失败。中间程序让两类错误可定位。
- **证据与边界。** WikiTQ 测试集的 Codex Binder 比同一模型的标准 SQL 语义解析高 3.5 个百分点。作者在 100 个错误样本中区分 Binder 使用错误、语义结构错误和执行错误，其中前三类占 32%、22%、15%。结果支持读出错在何处。人工修复用时未测。
- **工作动作。** GPU 事件联接、聚合与统计交给 SQL 或确定性 Python。日志的无结构归因只在必要位置请求模型，把标签连同原始片段和候选证据放回程序。保留来源、版本、分母及对应 run ID。对关键字段可由解析程序重验。
- **验证。** 在同一份 trace 中加入名称相似的两个 kernel、重复 correlation ID、以及无采样的空段。比较端到端解释、纯规则解析和局部模型判断。按字段、join、归因和最终结论逐层评分。若主要错误来自错误 join，应先修进程和关联键。若规则已能覆盖关键字段，减少模型调用。

### `arxiv:2212.04088`

- 原文：[LLM-Planner v3](https://arxiv.org/html/2212.04088v3)
- 范围：§§4.1–4.5、5.1–5.6，核对 Algorithm 1 的触发与计划前缀、Table 1–2 及未见环境结果。
- **方法。** 用少量配对示例和候选约束生成高层子目标。低层控制器负责执行。在当前子目标执行步数或失败数达阈值时，带入已经完成的前缀和当前可见对象，重新生成后续计划。示例由相似度检索得到。
- **证据与边界。** ALFRED 少样本实验用 100 对指令和高层计划。未见测试环境的 goal-only 配置中，动态规划比静态方案的成功率高 1.83 个百分点。与 SayCan 的调用数比较使用了额外的环境信息，且因 test metadata 限制未在测试分割评价该基线。观测可见性和低层控制质量限制收益。
- **工作动作。** 固定已通过的阶段。若某条采集或恢复路径连续失败，带实际 return code、最近可用样本及完成项改选后续动作。将环境状态未知保留为未知。例如只有 GPU 历史型号而缺当前工具权限时，先取已有控制面记录。
- **验证。** 用相同证据比较固定计划、连续同类失败才重规划，以及第一次关键状态改变就重规划。分别注入瞬时噪声与不可恢复错误。记录误触发、错过转换、重复成本和后续有效性。若确定性异常可以一次检测，先保留显式分支。

### `arxiv:2207.05608`

- 原文：[Inner Monologue v1](https://arxiv.org/html/2207.05608v1)
- 范围：§§3.1–3.3、4.1–4.3、6，核对 Table 3 的移动机器人扰动、反馈类型和 Appendix Table 5 的学习式观测入口。
- **方法。** 把技能成功或失败、环境中已见对象及场景描述转成语言反馈，再交给高层规划。被动反馈给状态变化。主动反馈允许向环境观察者提问。原实验部分场景的描述由人或脚本提供。
- **证据与边界。** 真实移动机器人三类任务的 120 次评价中，Table 3 的汇总列为 SayCan 30.8%、Success 48.7%、Success+Object 60.4%。在含干扰的移动操作切片，三列为 0%、25%、75%。成功判定会错，假阴性导致重试，假阳性造成状态丢失。论文也观察到模型有时忽略反馈。外部观察者质量与底层技能执行都会影响结论。
- **工作动作。** 在实验调度中给下一轮提供具体事实。用 run ID 对应的阶段、运行与否、是否有有效 trace、输出完整性分开表示。设计可主动查询缺失状态的接口。DeepInfer 观察器超时后，应核查服务器作业状态再决定恢复方向。
- **验证。** 用同一个复现问题比较只给摘要、给可检查的机器状态、以及状态加一项定向只读查询。注入错误成功标志与漏采场景。观察重复申请、过早停止和判断被新证据纠正的比例。若错误集中在 status detector，先修状态来源。

### `arxiv:2305.17390`

- 原文：[SwiftSage v2](https://arxiv.org/html/2305.17390v2)
- 范围：§§3.2–3.4、4.1–4.4、5 及附录的成本口径。核对 Table 1 的任务长度分层与每动作 token 对照。
- **方法。** Swift 用模仿学习处理常见动作，Sage 用模型先规划、再把子目标落成一小段动作。手工启发式负责切换，动作缓冲用完回到 Swift。规划器可以一次产出几步，减少每步重复输入上下文。
- **证据与边界。** ScienceWorld 上作者的 30 类任务平均得分为 84.68，ReAct 为 36.43。该指标是环境评分。每动作 token 为 757.07 对 1,971.03，口径不含 GPU 实验或人工返工。作者指出 Reflexion 获得不同重试预算，有些任务即使高分也未到满分，环境中的熟练技能和任务分布可能偏向快速模块。
- **工作动作。** 先用简单规则完成固定读取、schema 校验和已有进度恢复。工具受阻、状态矛盾或任务目标变化时才调用更深入调查。只有独立读数能预先定义的部分才缓冲执行。顺序依赖的提交动作需要等前一步证据。
- **验证。** 以相同任务与调用上限比较只用规则、全部开放调查、在预定义失败状态才升级三组。记录有效新证据、升级误报、漏掉关键异常、墙钟和预计 GPU 成本。若新增价值仅来自现有规则能表达的分支，就复用规则。若跨项目假阴性高，就修触发与证据输入。

### `arxiv:2502.08235`

- 原文：[The Danger of Overthinking v1](https://arxiv.org/html/2502.08235v1)
- 范围：§§3.1–3.3、4、5 的度量、环境设置、费用与工具对照。核对 SWE-bench Verified 的样本选择策略。
- **方法。** 对轨迹评分，识别反复计划但不取证、在没等反馈时连续执行相互依赖的动作，以及缺验证提前结束。评分器在看轨迹时不看修复结果。作者以低反复分数选择多个低预算候选之一。
- **证据与边界。** SWE-bench Verified 的 o1 设置中，单个低预算为 21.0% 和约 400 美元，两份低预算按评分选择为 27.3% 和约 800 美元，高预算为 29.1% 和约 1,400 美元。评分与结果关联不能推出分数本身是因。价格来自该次实验。工具调用对照还依赖调用架构与 benchmark。
- **工作动作。** 检查是否已获得能区分机制的读数。若继续思考只会重述现有假设，先用一项已授权的低成本读操作或保留未知。对两项相互依赖的实验操作，只有上一步结果满足已知条件才建议进入后一步。项目完成以产物或实测记录为据。
- **验证。** 让评审先看匿名、屏蔽结局的轨迹，再核对真实动作和证据。分别统计无观测重复、跳过前置条件和假完成。比较一次长分析、多个短候选、按需取证。若短候选只缩短时间但错过必要正确性检查，保留验证门槛。

### `arxiv:2509.09677`

- 原文：[The Illusion of Diminishing Returns v3](https://arxiv.org/html/2509.09677v3)
- 范围：§§2.1–2.2、3.1–3.3、5，核对 Figure 4–7 的状态和上下文干预，另看附录 A、C 对现实任务及自我复核的讨论。
- **方法。** 给模型显式的动作计划和查表项，要求它跨回合维护求和状态。分别改变总轮次、单轮要处理的键数量、前文错误率。把人工注入的错历史与修复到无错的同格式历史对照，区分长上下文影响和对先前错误的继续引用。
- **证据与边界。** 100 轮时，即使前文无错仍有准确率下降。注入更高历史错误率后，若干非推理模式进一步变差。所测 Qwen3 推理模式在这个受控任务上的准确率对注入较稳定。设计隔离了计划和知识，求和任务的动作及成功标准都比 Infra 窄。更长对话和更难单轮有不同预算结果。附录还讨论部分多样的行动基准。
- **工作动作。** 多轮调查把原始事件、可重算数值、当前假设及未证实的摘要分开保存。阶段转换时由原始快照重建必要状态。发现早期 GPU 版本或计时分母记错时，修源记录关联并回查受影响的判断。
- **验证。** 用匹配长度的历史前缀，分别保留原始证据、注入一条错误摘要、或用已验证快照替换摘要。固定同一新观测和决策问题。比较误差传播和重算成本。若简单快照解决主要问题，优先做好快照。若证据都正确仍在跨阶段失效，再检查上下文长度与调用策略。

## 对先验证哪类工作动作的影响

这些结果给三组可以区分的原因。目标和运算规则已确定时，优先测程序化提取或显式检查。环境状态改变时，先检验是否读到及时、可信的反馈，再比较按阈值和按证据重规划。多轮错误依赖旧结论时，先测试从证据重新生成状态。每类最小对照分别测错动作、遗漏的正确性门槛及成本。
