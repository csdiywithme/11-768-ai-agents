# L4 记忆与技能。从工作记录提取可验证的流程

核验日期 2026-11-13。以下逐项保留课程登记身份与实际读取的版本。正文机制、评估及边界按各项范围计。工程动作与反证是基于来源提出的验证设计。

### `arxiv:2409.07429`

- 原文：[Agent Workflow Memory v1](https://arxiv.org/html/2409.07429v1)
- 范围：L4 pp.26–29。读 §§2.1–2.3、3.1–3.2、4.1–4.3，核查 WebArena 与 Mind2Web 的不同切分和 Tables 4–8。
- 机制：把观察、理由和动作抽成带占位符的通用子流程。离线法用已有示范，在线法把任务流中模型判成功的轨迹加入归纳。产物作为上下文辅助动作选择。
- 证据与条件：WebArena 消融中规则归纳和模型归纳总成功率为 35.6% 与 35.5%，模型归纳平均步数为 5.9，规则为 6.3。Mind2Web 跨域的整任务成功率很低，离线和在线为 0.7% 与 1.7%，对应基线 1.0%。跨网站上在线版步骤成功率略高，但整任务成功率低于离线版。作者还观察到错误归纳与不应遵循旧流程的情形。
- 工程动作与反证：从已完成的实验提取小流程，写明输入、可观察状态和该步骤适用的前提。比较人工固定规则、参数化示范、从历史记录自动归纳的说明。在不同版本和形状上分别统计整任务正确、局部选择正确和主动工时。若简单规则的表现相当，则无需增加在线更新。
- 作者仓库扩展：README 给出 WebArena 和 Mind2Web 的独立入口，后者可分离在线和离线运行。本轮读 Quickstart 和实现概览，未运行。 [AWM README](https://github.com/zorazrw/agent-workflow-memory/blob/main/README.md)

### `arxiv:2410.08164`

- 原文：[Agent S v1](https://arxiv.org/html/2410.08164v1)
- 范围：L4 p.20 与 L5 reading。读 §§3.1–3.3、4.1–4.5，核查 Tables 1–4 的全量与消融子集。
- 机制：Manager 用外部知识与完整任务经验排列有依赖的子任务。Worker 检索子任务经验并根据执行反馈继续。两种记忆按粒度保存，任务级摘要可包含失败。Agent-Computer Interface 提供可定位的动作与观察。
- 证据与条件：GPT-4o 在 OSWorld 369 个任务的总体结果为 20.58%，对应基线 11.21%。65 个任务的消融中完整 26.15%，移除 episodic memory 18.46%，移除 narrative memory 21.41%。整套架构同时改变计划、工具和记忆。失败分析中同一个任务可有计划、定位和执行多种错误。
- 工程动作与反证：任务级保留优化目标、约束与多步实验因果。操作级保留 profiler 导出、trace 关联和失败恢复的输入、结果和查证方法。分别移除两种记忆，检查错误是否集中在依赖顺序、工具调用或结论。若错误主要来自操作接口，先修接口。独立测量实际人工时间，避免把 GUI 完成率当工程收益。

### `arxiv:2306.07863`

- 原文：[Synapse v3](https://arxiv.org/html/2306.07863v3)
- 范围：L4 p.20。读 §§3.1–3.4、4.1–4.5、§5，重点核对 Table 2 的跨任务、网站、域对照及 Fig. 5。
- 机制：将原始状态抽成任务相关观察，把整条成功轨迹作为示范，通过任务元数据的向量检索匹配示范。示范保存连续观察和动作，能表达单步说明难以覆盖的执行历史。
- 证据与条件：Mind2Web Table 2 的 GPT 步骤成功率增量依次为 1.4、1.5、0.2 个百分点，CodeLlama 的跨域值为 −0.2。状态筛选也可能漏关键信息。论文对照里把候选网页元素从 50 缩到 5 后，元素召回从 86% 降至 53%，后续动作生成方式也变化。
- 工程动作与反证：短 trace 示范保留先观察、再定位、再验证的因果序列与原始路径。先按 commit、设备、拓扑和指标口径过滤，再选择示范。用陌生后端和同名异义事件测试。若摘要引起漏读或相似示范拉低跨后端表现，优先让工具返回原始信号或限制示范适用范围。

### `arxiv:2406.14596`

- 原文：[ICAL v6](https://arxiv.org/html/2406.14596v6)
- 范围：L4 p.20。读 §§3.1–3.4、4.1–4.7、§5，核查 TEACh 的 Table 1、视觉任务的 Table 2 和 Figure 5。
- 机制：把不完美示范转成结构化动作与原因，尝试执行并接受简短人工纠正。达到结果要求后才保存为示范。可用检索或监督微调部署。Ego4D 是被动预测任务，没有执行中的人工纠正。
- 证据与条件：TEACh unseen、真值感知设置下，原始视觉示范、带真实动作的示范、ICAL 检索的任务成功率为 17.2%、26.5%、35.1%。去掉人工反馈为 29.9%。估计感知时，ICAL 为 10.5%，手写 HELPER 为 8.3%。输入观测与专家可验证性会限制迁移。
- 工程动作与反证：给一组历史 profile 短轨迹补人审，要求纠正具体观测、失效的比较口径和下一项可区分动作。用新任务对照原轨迹、模型改写、人审改写，测关键错误与审阅成本。若人审仍无法稳定确认关键路径，先改数据采集与判据，保留该类样本为不确定。

### `arxiv:2006.08381`

- 原文：[DreamCoder v1](https://arxiv.org/pdf/2006.08381v1)
- 范围：L4 p.23。读 PDF 正文 pp.3–8 的三阶段学习和 pp.10–13 的跨域消融及 Fig. 6 讨论。未复现程序合成。
- 机制：搜索阶段用神经识别模型提出候选程序，用可执行任务判据筛选。抽象阶段找公共片段加入程序库。随后从旧经验和该库生成可求解的合成任务，训练提出候选的识别模型。任务分布、库和搜索器共同决定效果。
- 证据与条件：作者在 LOGO 和 tower building 的留出任务报告，完整方法接近解决全部，替代方法没有超过 60%。收敛随领域变化，文中典型计算量约为 20–100 CPU 用一天。小量可执行输入输出与初始 DSL 是实验前提。
- 工程动作与反证：从已验证的工作记录抽取可组合的测量操作。用另一个版本、硬件或 trace 样例跑接口回归，比较复用是否缩短寻找下一条证据的时间。合成验证可覆盖格式与状态变体。若合成分布漏掉真实失败类型，或没有可复查判据，优先补数据契约和真实样本。

### `arxiv:2211.16605`

- 原文：[Stitch v2](https://arxiv.org/html/2211.16605v2)
- 范围：L4 p.23。读 §§2–3 的自顶向下搜索、§4 压缩度量、§§6.1–6.5 实验段，核查 Tables 1–3 及与重写推导的互补性。
- 机制：用语料的程序树引导搜索可提取的 lambda 抽象。逐步填洞只会缩小匹配位置集合，能据此计算压缩收益上界并剪枝。每轮抽取一个抽象，再重写语料继续。
- 证据与条件：作者用 DreamCoder 保存的训练解比较抽象质量，并匹配每轮抽象数。质量指标是程序树压缩，作者也展示图形 DSL 中的资源结果。不同写法可表达同一行为，演绎重写仍能揭示单纯语法匹配看不到的共性。压缩率无法直接表示下游软件维护成本或正确性。
- 工程动作与反证：从重复的计时汇总、阶段解析和配对验证中找共用步骤。抽象先保留明确的参数、返回值和原始输出约束。拿两种语义不同但命令相似的日志做反例，比较脚本复用前后错误与审阅时间。若抽象隐藏关键指标口径，维持较小的单功能操作。

### `arxiv:2310.19791`

- 原文：[LILO v4](https://arxiv.org/html/2310.19791v4)
- 范围：L4 p.23。读 §§2–3 方法选段、§§4.1–4.2、§5，核对 Table 1 的三种任务、各搜索与 AutoDoc 消融。
- 机制：结合模型提出的程序和受控枚举，执行后将成功解交给 Stitch 压缩，最后生成函数名和文档。冻结所得库后，作者还以同样枚举设置检验库的独立贡献。
- 证据与条件：在线 REGEX 中，只用 LLM Solver 的平均成功率为 76.13%，加入匿名压缩、无枚举与 AutoDoc 的条件为 53.20%。增加 AutoDoc 后为 62.93%。完整 LILO 为 77.07%。LOGO 中仅增加 AutoDoc 的均值没有提高。作者检查到文档可能给函数赋错含义。结果限于 REGEX、CLEVR 和 LOGO DSL。
- 工程动作与反证：给采集、解析、配对验证函数写清签名、单位和可核查示例。对同一套函数交替提供原名、经验证的文档与自动生成文档，测陌生任务的正确选用和报告一致性。若文档诱导模型用错指标，优先让契约和示例可执行检查。

### `arxiv:2401.12869`

- 原文：[TroVE v1](https://arxiv.org/html/2401.12869v1)
- 范围：L4 p.42。读 §§3.1–3.3、5.1–5.4、§6，核查 Table 3 和人工复核 Table 5。
- 机制：对同一输入分别尝试复用函数、新建函数、只用原语。先执行并剔除无效，再按输出一致性和调用复杂度选方案。随任务流裁剪低使用函数。多数一致来自候选生成与执行，并未替代外部正确性判据。
- 证据与条件：WTQ 100 个样本、6 位人工评审中，原语、每题定制与可复用方案的平均验证用时为 25.5、30.7、17.5 秒，检测准确率分别 0.77、0.88、0.87。其它基准含数学、表格和视觉 QA。罕见但关键的工具可能在按频率裁剪时丢失。
- 工程动作与反证：同一组工单比较现成脚本、每次生成脚本、带维护记录的小工具库。记录人审用时、证据错配和关键条件漏查。多个解析器同意也要核对原始计时与对照。按重要性保留罕用诊断，若小库降低关键失败场景覆盖，则恢复明确入口。

## 工作流、工具和示范的对照

- 先用已有脚本或人工流程作基线。把「运行阶段可判断」和「需要调查才能选下一步」分开标注。比较任务级经验、步骤级示范和可执行工具的增量。
- 单项目的技能有效时，补另一个版本、GPU 或框架的适用性检查。单独记录准备工具的时间、执行次数和人工审查成本。保留未参与抽取的新任务检验迁移。
