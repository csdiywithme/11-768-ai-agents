### `arxiv:2510.23691`

- 原文：[Game-TARS · v1](https://arxiv.org/html/2510.23691v1)
- 范围：§2–4 的统一动作、稀疏推理监督、动作损失、分层记忆及跨环境评估。核对 §3.3、§4.3.2 和 Table 4。
- 方法：视频、键鼠动作和人工口述按时间对齐。对连续相同动作的训练损失逐步降权，保留等待等行为。先找只预测动作时的错误位置，再补能导向参考动作的判断说明。新近轨迹保存细节，较旧内容保留摘要。
- 证据及边界：Minecraft 表中稀疏推理为 63%，无推理 55%，逐步推理 45%。稀疏与逐步推理平均每步 37 和 68 token。Doom 上无推理更高，2048 上逐步推理更高。浏览器部分冻结游戏时间以容纳模型延迟，因此基准分也依赖交互时钟和动作采样方式。
- 工作迁移：在 GPU 实验中，启动计时、收集文件和轮询可交给确定性工具。选择比较对象、解释反常计数或停止分支时增加推理。标注数据重点保留决定行动改变的观测，同时保留少量代表性等待或重复步骤。
- 最小验证：对同一任务用逐步模型推理、按异常触发重规划、固定脚本三个方案，加入一次配置漂移和一次正常的慢任务，测误动作、无效重跑、模型时间和最终验证率。

### `arxiv:2512.19432`

- 原文：[MobileWorld · v3](https://arxiv.org/html/2512.19432v3)
- 范围：§3–4 的任务类别、Android 环境、交互和 MCP 工具、任务验收、50 步对比及误差分析。核对 Table 4、6–7。
- 方法：在可重置的 Android 环境中区分纯 GUI、需要向模拟用户询问、需要 GUI 与 MCP 协作三类任务。共 201 项，类别分别为 116、45、40 项。验收通过应用回调、文字匹配、存储状态或后端数据库实施。用户模拟器持有题目省略的信息。
- 证据及边界：GPT-5 加 UI-Ins-7B 在作者配置下整体 51.7%，澄清类 62.2%，MCP 类 51.6%。部分模型只覆盖兼容任务，整体数字还受工具能力限制。问得多仍可能问错，工具调用数也未衡量参数有效与结果使用。外部 MCP 数量在正文与汇总表有 61 和 64 两种口径。
- 工作迁移：把请求分成现有工件可确定、缺一项用户约束、需要组合外部元数据和本地 trace。允许助手先做独立的只读准备。GPU 预算或目标 SLO 会改变实验选择时，问具体参数并记录回答产生的决策变化。
- 最小验证：给三个版本的性能工单，分别包含完整 SLO、可从现有配置找到的 SLO 和必须澄清的 SLO。固定执行工具，计有效提问、重复提问、工具参数错误、是否在当前约束下选对实验。

### `arxiv:2607.28227`

- 原文：[Qwen-UI-Agent Technical Report · v1](https://arxiv.org/html/2607.28227v1)
- 范围：§2.2–2.5 的异构环境、GUI 与 CLI、任务与验收生成、SFT/Action RL/Online RL 和执行层，及 §3.3 结果。重点看 Table 5、8。
- 方法：将真实设备、沙箱和网页统一接入，动作可批量生成并在不同界面间切换。按任务相关环境状态生成任务，再独立筛选并以多个模型轨迹校验约 10,000 对任务与验收器。Action RL 针对选错控件、错误排序、重复、过早完成等局部错误。Online RL 按最终状态评分，跟踪任务何时从全错或全对变为仍有学习信号。
- 证据及边界：27B 在 OSWorld-v2 得到 40.0% 部分分和 13.9% 严格完成，报告的平均步骤为 135.8，使用批量动作。ScreenSpot-Pro 不缩放为 76.6%，允许缩放为 81.5%。这些属于作者配置的基准对比。报告同时改变训练、界面协议和执行环境，单项机制的增量需另行控制。
- 工作迁移：从已有优化记录归纳重复失败，如选错 trace、只改 kernel 未跑正确性、把不同 GPU 的结果合并。局部错误可由 schema、工具验证或修复示范解决。跨阶段协调和决策质量需要最终任务级验收，决定是否继续投入轨迹数据。
- 最小验证：对同一批回放工单比较现有提示、加局部动作约束、加独立最终验证。记录错误参数、提前结束、吞吐和复跑开销。保留一个不同 engine 的留出集合检查规则是否只适用于当前工具。
